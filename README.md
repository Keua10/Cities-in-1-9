## 2. 이번 STEP 3.1에서 구현할 건물 성장/재개발 시스템 (확정 설계)

### 2.1 건물 등급 (계층)

- 모든 존(주거/상업/공업)에 공통 적용되는 3단계 계층:
  - **L1 (저소득)**: 1×1 타일
  - **L2 (중산층)**: 2×2 타일
  - **L3 (고소득)**: 3×3 타일
- 계층이 높을수록 만족도(satisfaction) 임계값이 더 엄격함 (L1 < L2 < L3)

### 2.2 신규 건설 (New Construction)

- 빈 필지(empty lot)에 대해 계층별 수요 비율(demand ratio)에 따라 어떤 등급의 건물을 지을지 결정
- 구현 시 참고: 수요 비율 → 건물 등급 선택 → 필지 크기(1x1/2x2/3x3)에 맞는 빈 공간 탐색 → 건설

### 2.3 재개발 (Redevelopment) — 상향식만 존재

- **하향 재개발은 없음.** 수요/만족도가 계층 기준 미달이 되면:
  - 거주자/입주자는 빠져나감 (occupancy = 0)
  - 건물 자체는 물리적으로 남아있음 (빈 건물 = vacant building, 철거되지 않음)
- **상향 재개발 트리거 조건**: 해당 위치 주변 범위 내에 빈 필지가 전혀 없을 때만 발동
- **트리거 시 검증**: 재개발 대상 footprint에 포함되는 모든 타일이 **동시에** 재개발 조건을 만족해야 함 (일부 타일만 조건 충족 시 재개발 불가)

### 2.4 공실 탐지 (Vacancy Detection) — 재개발 트리거 판정용

- **섹터 기반**: 16×16 타일 섹터 단위로 관리
- 판정 시 확인 범위: 자기 섹터 + 인접 8개 섹터 (총 9섹터)
- 이 범위 내에 빈 필지가 없으면 → 해당 섹터 내 상향 재개발 후보 탐색 시작

### 2.5 저장 방식 (매 틱 결정론적 재계산 원칙)

- **저장되는 것**: 건물의 물리적 상태만 (`bld`, `bornLo`, `bornHi` 등)
- **저장되지 않고 매 틱 재계산되는 것**: 점유율(occupancy), 만족도(satisfaction)
  - 즉, 저장된 물리적 상태 + 현재 인프라/수요 상황을 바탕으로 매 틱 occupancy/satisfaction을 결정론적으로 다시 계산
  - 서버(오프라인 캐치업)와 클라이언트가 같은 입력에 대해 항상 같은 결과를 내야 함 (재현성 필수)

## 3. 이번 핸드오프에서 GPT가 할 일 (체크리스트)

- [ ] 계층별(L1/L2/L3) 건물 데이터 구조 정의 (`bld`, `bornLo`, `bornHi` 등 물리 상태 필드 포함)
- [ ] 신규 건설 로직: 구역별 수요 비율 계산 → 등급 결정 → 빈 필지(1x1/2x2/3x3) 탐색 → 건설
- [ ] 섹터 기반 공실 탐지 함수 구현 (16×16 섹터, 자기+인접 8섹터 스캔)

- [ ] 빈 건물(vacant building) 상태 처리: 철거되지 않고 물리적으로 남아있는 상태를 렌더링/데이터 상 올바르게 표현
- [ ] `npm run build` (TypeScript 타입체크 + Vite 빌드) 통과 확인

## 7. GPT 수정·검증 결과

- 재개발 포화 판정을 청크 단위에서 **16×16 타일 섹터 단위**로 교체했습니다. 후보가 속한 섹터와 인접 8개 섹터(총 9개)에 빈 필지가 하나라도 있으면 재개발하지 않습니다.
- 재개발은 현재 섹터의 후보만 검사하며, 목표 footprint의 모든 타일이 같은 지구·고도, 기존 건물 존재, 최소 나이, 상향 등급 조건을 동시에 만족해야 실행됩니다.
- occupancy/satisfaction은 저장하지 않고 현재 물리 건물·도로망·수요에서 결정론적으로 다시 계산합니다. 만족도 기준 미달 건물은 철거하지 않고 occupancy 0의 공실로 남습니다.
- HUD에서 선택한 건물의 `공실` 또는 `입주 N%` 상태를 확인할 수 있고, 도시 패널에는 전체 공실률을 표시합니다.
- 건물 아틀라스 `public/sprites/buildings.png`는 투명 배경의 도트 그래픽입니다. 픽셀 비율은 **타일당 64px**이며 L1/L2/L3 셀은 각각 64×64px, 128×128px, 192×192px입니다.
- 건물 원화의 실질 도트 크기인 **4×4px 블록**에 맞춰 지형 표면, 절벽, 도로, 중앙선, 연석, 지구 표시와 고도 음영도 같은 4px 도트 그리드로 통일했습니다. 부드러운 그라데이션과 안티앨리어싱 선은 사용하지 않습니다.
- 기존 확정값인 `WORLD_SEED`, `TILE_W`, `TILE_H`, `HEIGHT_UNIT`, `CHUNK_SIZE`, 지형 노이즈 함수, 청크 메시 구조는 변경하지 않았습니다.
- 시작 자금과 수요 비율은 원래 STEP 3.1 값으로 복구했으며, 범위 제외 항목은 수정하지 않았습니다.
- `npm run build`와 시뮬레이션 검증(섹터 경계 빈 필지 탐지, footprint 전체 L1→L3 상향 재개발, 220일 성장·재정)을 통과했습니다.
