# 1-9 도시 — 0단계: 렌더링 골격

아이소메트릭 지도, **고도(언덕·절벽)**, 카메라 조작, 청크 스트리밍, 안개까지
돌아가는 상태입니다. Firebase·도로·차량·시뮬레이션은 아직 없습니다(1단계 이후).

---

## 1. 깃허브 + Vercel 세팅 (처음 한 번)

```bash
git init
git add .
git commit -m "0단계: 렌더링 골격"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

Vercel 에서 **Add New → Project → 저장소 선택 → Deploy** 만 누르면 됩니다.
Vite 프로젝트로 자동 인식되고 따로 설정할 게 없습니다.

- 빌드 명령 `npm run build`, 출력 폴더 `dist` — 둘 다 자동으로 잡힙니다.
- 이후 `main` 에 push 할 때마다 자동 재배포됩니다.

`npm run build` 안에 타입 검사가 들어 있습니다. **타입이 깨지면 배포가 실패하고
기존 배포는 그대로 살아 있습니다.** GPT 가 코드를 잘못 고쳤을 때 학생들이 보는
사이트가 깨지는 걸 막아주는 안전장치이니 빼지 마세요.

### 패드와 컴퓨터를 오가는 작업 흐름

아이패드에서는 `npm` 을 못 돌리니 역할을 나누는 게 편합니다.

| | 컴퓨터 | 아이패드 |
|---|---|---|
| 코드 수정 | 에디터에서 직접, `npm run dev` 로 즉시 확인 | github.dev 웹 에디터로 수정 후 커밋 |
| 확인 | `localhost:5173` | Vercel 배포 URL (실기기 터치 테스트) |

아이패드 브라우저에서 저장소 주소의 `github.com` 을 **`github.dev`** 로 바꾸면
웹에서 바로 편집·커밋이 됩니다. 커밋하면 1~2분 뒤 Vercel 에 반영됩니다.

큰 수정을 할 때는 브랜치를 파세요. `main` 이 아닌 브랜치에 push 하면 Vercel 이
**미리보기 URL**을 따로 만들어 줍니다. 학생들이 보는 주소는 그대로 두고 거기서
확인한 뒤, 괜찮으면 `main` 에 합치면 됩니다.

```bash
git switch -c hills-test
git push -u origin hills-test
```

작업 시작 전엔 항상 `git pull` 부터. 패드에서 커밋한 걸 컴퓨터가 모르는 상태로
작업하면 충돌이 납니다.

## 2. 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입 검사 + dist 생성
```

| 동작 | 터치(아이패드) | PC |
|---|---|---|
| 이동 | 한 손가락 끌기 (관성 있음) | 드래그 |
| 확대/축소 | 두 손가락 핀치 | 휠, 트랙패드 핀치 |
| 타일 선택 | 짧게 탭 | 클릭 / 마우스 올리기 |

아래 버튼으로 안개와 청크 격자를 껐다 켤 수 있습니다. 안개를 끄면 아직 개척하지
않은 청크의 지형까지 보이므로 지형 생성을 확인할 때 쓰면 됩니다.

## 3. 파일 구조

```
src/
  main.ts                 부팅, 툴바, 매 프레임 루프
  style.css               캔버스·HUD·툴바 CSS
  core/
    constants.ts          ★ 모든 규격 상수 (타일·청크 크기, 고도 단계, 시드, 예산)
    iso.ts                ★ 좌표계 정의 — 타일↔월드↔청크 변환
    pick.ts               고도를 고려한 타일 찍기
    camera.ts             카메라 (관성, 범위 제한, 한 점 고정 확대)
    input.ts              포인터 입력 (팬/핀치/휠/탭)
  world/
    terrain.ts            ★ 결정론적 지형·고도 생성
    world.ts              청크 저장소, 안개 상태, 육각 격자 base 배치
  render/
    atlas.ts              아틀라스 로딩 + 임시 타일·고도 음영 자동 생성
    chunkMesh.ts          ★ 청크 1개 = 메시 1개 = 드로우콜 1회
    worldRenderer.ts      청크 스트리밍, 안개, 격자, 커서
  ui/
    hud.ts                개발용 상태 표시
public/sprites/
  terrain_template.png    그림 작업용 가이드 이미지
```

### 성능에서 중요한 부분

타일 4,096개를 스프라이트 4,096개로 만들면 아이패드에서 청크 몇 개만 띄워도
프레임이 무너집니다. `chunkMesh.ts` 는 청크 하나를 **정점 버퍼 하나**로 구워서
**드로우콜 1회**로 그립니다. 타일 하나가 바뀌면 그 타일의 UV 8개만 고쳐 씁니다.
2단계에서 도로를 그을 때도 이 경로(`ChunkMesh.setTile`)만 타면 됩니다.
**이 구조를 스프라이트 방식으로 되돌리지 마세요.**

실측: 청크 하나당 사각형 약 5,600개(윗면 4,096 + 절벽 약 80 + 고도 음영 약 1,400),
정점 버퍼 약 360KB. 화면에는 보통 청크 10~25개가 올라갑니다.

## 4. 고도가 어떻게 동작하나

- 고도는 **0~8 단계**, 한 단계가 화면에서 16px 입니다.
- 지형 생성 함수가 고도를 함께 만듭니다. 저장하지 않고 좌표에서 매번 계산합니다.
- **이웃 타일 간 고도 차이는 항상 0 아니면 1 단계**입니다. 60만 개 지점을 검사해
  확인했습니다. 절벽은 한 칸씩 계단으로 올라가고, 산은 여러 타일에 걸쳐 층으로
  쌓입니다. 2단계의 도로 경사 판정은 이 성질에 기대면 됩니다.
- 절벽 옆면은 두 방향만 그립니다(오른쪽 아래 = +tx, 왼쪽 아래 = +ty).
  나머지 두 면은 카메라에서 안 보이므로 아예 만들지 않습니다.
- 고도가 높을수록 윗면을 살짝 밝게 덮습니다. 이 음영 칸은 **코드가 자동 생성**해
  아틀라스 뒤에 붙입니다 — 그림 작업 대상이 아닙니다.
- 물은 항상 고도 0 이고, 해안에서는 고도가 완만하게 올라옵니다(해안 절벽 방지).

넓은 영역 400만 지점 표본: 물 30%, 모래 9%, 풀·마른풀 41%, 숲 11%, 흙 3%,
바위산 5.5%. 고도는 0단계가 48%, 나머지가 1~8단계에 퍼집니다.

> **나중에 쓸 확장 지점**: 고도 음영과 똑같은 방식으로 아틀라스에 칸만 추가하면
> 영토 색, 오염 히트맵, 상하수도 커버리지 같은 타일 단위 색 오버레이를 셰이더
> 없이 그릴 수 있습니다. 6단계의 영토 표시는 이걸로 갑니다.

## 5. 그림 규격 (GPT 작업의 기준)

`public/sprites/terrain.png` 를 만들어 넣으면 코드가 자동으로 그걸 씁니다.
없으면 임시 타일이 자동 생성되므로 그림 없이도 게임은 돌아갑니다.
HUD 에 "그림: 임시 타일 사용 중" 이 뜨면 아직 임시 타일입니다.

- 전체 크기 **544 × 72 px** (가로 8칸 × 세로 2줄), PNG-32.
- **셀 크기 68 × 36 px.** 바깥 2px 은 반드시 완전 투명한 여백입니다(색 번짐 방지).
- 안티에일리어싱 금지. 가장자리에 반투명 픽셀이 있으면 타일 경계에 실선이 생깁니다.
- `terrain_template.png` 에 셀 경계(빨강), 그림 영역(노랑), 모양 가이드(청록)가
  그려져 있습니다. 가이드 선은 지우고 그 위에 그리세요.

### 0번 줄 — 지형 윗면 8칸

그림 영역은 셀 안쪽 **64 × 32**, 다이아몬드 꼭짓점은 (32,0) (63,16) (32,31) (0,16).
다이아몬드 밖은 투명하게 둡니다.

| 칸 | 이름 | 설명 |
|---|---|---|
| 0 | water_deep | 깊은 물 |
| 1 | water_shallow | 얕은 물 / 물가 |
| 2 | sand | 모래 |
| 3 | grass | 풀 |
| 4 | grass_dry | 마른 풀 |
| 5 | dirt | 흙 |
| 6 | rock | 바위 |
| 7 | forest | 숲 |

### 1번 줄 — 절벽 옆면 4칸

그림 영역은 셀 안쪽 **32 × 32** 안의 평행사변형입니다.

| 칸 | 이름 | 평행사변형 윗변 |
|---|---|---|
| 8 | soil_left | (0,0) → (31,16) — 왼쪽 아래를 향한 면 |
| 9 | soil_right | (0,16) → (31,0) — 오른쪽 아래를 향한 면 |
| 10 | rock_left | 8번과 같은 모양, 바위산용 |
| 11 | rock_right | 9번과 같은 모양, 바위산용 |

빛은 오른쪽 위에서 온다고 보고 **right 면을 left 면보다 밝게** 그려야 입체로
보입니다. 세로로 반복되므로 위아래로 이어 붙였을 때 자연스러워야 합니다.

> 2번 줄부터는 코드가 고도 음영을 자동으로 채웁니다. **그림 파일에 넣지 마세요.**
> 지형 종류를 늘리려면 `world/terrain.ts` 의 `Terrain`·`TERRAIN_KEYS` **끝에**
> 추가하고 아틀라스 0번 줄 뒤에 칸을 붙이면 됩니다. 중간에 끼우면 전부 밀립니다.

## 6. GPT 에게 넘길 작업

우선순위 순입니다.

1. **타일 그림 12칸** — 위 규격대로 `public/sprites/terrain.png` 제작.
   지형 8칸과 절벽 4칸이 같은 파일에 들어갑니다.
2. **아이패드 실기기 확인** — Safari 에서 핀치가 브라우저 확대로 새지 않는지,
   한 손가락 이동이 페이지 스크롤로 새지 않는지. 새면 `style.css` 의
   `touch-action: none` 적용 범위를 먼저 의심하세요.
3. **성능 측정** — 아이패드에서 최대 축소(배율 0.2)로 HUD 의 fps 확인.
   60fps 가 안 나오면 `constants.ts` 의 `CHUNK_MESH_BUDGET`(현재 28)을 줄이거나
   `MIN_ZOOM`(현재 0.2)을 올리세요. 이 둘이 성능 조절 손잡이입니다.
4. **고도 느낌 조정** — `terrain.ts` 의 `HILL_SCALE`(언덕 크기),
   `HILL_WEIGHT`(언덕 비중), `constants.ts` 의 `MAX_HEIGHT` 세 개로 조절합니다.
   **바꾼 뒤엔 반드시 이웃 고도 차이가 1을 넘지 않는지 다시 확인하세요.**
   넘으면 절벽이 두 칸으로 겹쳐 그려지고 2단계 도로 규칙이 깨집니다.
5. **Pixi 버전 확인** — `pixi.js ^8.6` 기준입니다.
   `ChunkMesh.flush()` 의 `geometry.getBuffer('aUV').update()` 와
   `ChunkMesh.destroy()` 가 버전에 따라 이름이 다를 수 있는 두 군데입니다.
   화면이 안 뜨면 여기부터 보세요.

### 손대면 안 되는 것

- `constants.ts` 의 `WORLD_SEED`, `TILE_W/H`, `HEIGHT_UNIT`, `CHUNK_SIZE` —
  바꾸면 이미 만든 도시가 전부 어긋납니다.
- `terrain.ts` 의 `hash2`, `valueNoise`, `fbm` — 서버(Vercel 함수)도 똑같은 값을
  계산해야 합니다. 여기서 `Math.random` 을 쓰거나 식을 고치면 지형이 갈라집니다.
- `iso.ts` 의 변환식 — 이 파일이 좌표계의 유일한 기준입니다.
- `chunkMesh.ts` 의 사각형 순서 — 절벽·윗면·음영의 순서가 곧 그리는 순서입니다.
  순서를 바꾸면 산 뒤의 타일이 앞으로 튀어나옵니다.

## 7. 0단계에서 일부러 뺀 것

| 항목 | 언제 | 지금 상태 |
|---|---|---|
| Firebase 로그인·저장 | 1단계 | 도시 번호 0번 고정 (`main.ts`) |
| 도로·지구 지정 | 2단계 | `World.setTile` / `ChunkMesh.setTile` 만 뚫려 있음 |
| 건물·차량 스프라이트 레이어 | 2~4단계 | 지면 레이어만 있음 |
| 지형 편집(터레이닝) | 미정 | `World.setHeight` 가 있고 렌더러가 메시를 다시 굽는다 |
| 안개 개척 | 5단계 | `World.explore()` 만 있고 조건은 없음 |
| 산에 가려진 시야, 바람 방향 | 6단계 | 고도 데이터가 있으니 계산은 바로 가능 |

## 8. 다음 단계 (새 채팅)

**1단계: 데이터 모델 + Firebase 스키마 + 로그인 + 저장/불러오기.**

핵심 설계는 **지형은 저장하지 않는다** 입니다. 지형과 고도는 시드에서 다시
계산되므로, Firestore 에는 "생성값과 달라진 타일"과 매크로 상태(인구·돈·수요)만
저장합니다. 학생 한 명당 저장 용량이 수십 KB 로 떨어져 Spark 무료 한도 안에서
돌아갑니다.
