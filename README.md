# 1-9 도시 — 1단계: 로그인 + 저장/불러오기

아이소메트릭 지도, 고도(언덕·절벽), 카메라 조작, 청크 스트리밍, 안개(0단계) 위에
**Firebase 로그인과 Firestore 저장/불러오기**가 붙었습니다.
도로·건물·차량·시뮬레이션은 아직 없습니다(2단계 이후).

핵심 규칙은 **지형은 저장하지 않는다** 입니다. 지형과 고도는 좌표와 시드에서
항상 같은 값이 나오므로 매번 다시 만들고, Firestore 에는 "생성값과 달라진 칸"과
도시 상태만 들어갑니다. 학생 한 명당 저장 용량이 수십 KB 로 떨어집니다.

## 1. 깃허브 + Vercel 세팅 (처음 한 번)

```bash
git init
git add .
git commit -m "0단계: 렌더링 골격"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

Vercel 에서 **Add New → Project → 저장소 선택 → Deploy** 만 누르면 됩니다.
Vite 프로젝트로 자동 인식되고 따로 설정할 게 없습니다.

- 빌드 명령 `npm run build`, 출력 폴더 `dist` — 둘 다 자동으로 잡힙니다.
- 이후 `main` 에 push 할 때마다 자동 재배포됩니다.

`npm run build` 안에 타입 검사가 들어 있습니다. **타입이 깨지면 배포가 실패하고
기존 배포는 그대로 살아 있습니다.** GPT 가 코드를 잘못 고쳤을 때 학생들이 보는
사이트가 깨지는 걸 막아주는 안전장치이니 빼지 마세요.

### 패드와 컴퓨터를 오가는 작업 흐름

아이패드에서는 `npm` 을 못 돌리니 역할을 나누는 게 편합니다.

| | 컴퓨터 | 아이패드 |
|---|---|---|
| 코드 수정 | 에디터에서 직접, `npm run dev` 로 즉시 확인 | github.dev 웹 에디터로 수정 후 커밋 |
| 확인 | `localhost:5173` | Vercel 배포 URL (실기기 터치 테스트) |

아이패드 브라우저에서 저장소 주소의 `github.com` 을 **`github.dev`** 로 바꾸면
웹에서 바로 편집·커밋이 됩니다. 커밋하면 1~2분 뒤 Vercel 에 반영됩니다.

큰 수정을 할 때는 브랜치를 파세요. `main` 이 아닌 브랜치에 push 하면 Vercel 이
**미리보기 URL**을 따로 만들어 줍니다. 학생들이 보는 주소는 그대로 두고 거기서
확인한 뒤, 괜찮으면 `main` 에 합치면 됩니다.

```bash
git switch -c hills-test
git push -u origin hills-test
```

작업 시작 전엔 항상 `git pull` 부터. 패드에서 커밋한 걸 컴퓨터가 모르는 상태로
작업하면 충돌이 납니다.

## 2. Firebase 세팅 (처음 한 번)

### 2-1. 프로젝트 만들기

1. [console.firebase.google.com](https://console.firebase.google.com) → **프로젝트 추가**.
   Google 애널리틱스는 **끄세요**(필요 없고 설정만 늘어납니다).
2. 프로젝트 안에서 **웹 앱 추가**(`</>` 아이콘). 앱 이름은 아무거나.
   Firebase Hosting 체크는 **하지 마세요** — 배포는 Vercel 이 합니다.
3. 마지막에 나오는 `firebaseConfig` 에서 네 값을 복사해 둡니다.
   `apiKey`, `authDomain`, `projectId`, `appId`

### 2-2. 로그인 켜기

**Authentication → 시작하기 → 이메일/비밀번호** 를 켭니다.
"이메일 링크(비밀번호 없는 로그인)" 는 끈 채로 둡니다.

### 2-3. Firestore 켜기

**Firestore Database → 데이터베이스 만들기 →** 위치는 `asia-northeast3`(서울),
모드는 **프로덕션 모드**로 시작합니다. 그다음 **규칙** 탭에
저장소의 `firestore.rules` 내용을 통째로 붙여넣고 **게시**를 누릅니다.

> 테스트 모드로 두면 30일 뒤에 전부 잠기고, 그 전까지는 아무나 남의 도시를
> 지울 수 있습니다. 규칙은 반드시 붙여넣으세요.

### 2-4. 환경변수 넣기

`.env.example` 을 `.env` 로 복사해 값을 채우면 내 컴퓨터에서 돌아갑니다.
Vercel 에는 **Settings → Environment Variables** 에 같은 이름으로 네 개
(`VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`,
`VITE_FIREBASE_APP_ID`)를 넣고 다시 배포하면 됩니다.

이 네 값은 **원래 공개되는 값**입니다. 브라우저 개발자 도구에서 다 보입니다.
보안은 `firestore.rules` 가 담당하니 노출을 걱정할 필요 없습니다.
진짜 비밀(서비스 계정 키)은 앞으로도 `VITE_` 로 시작하게 두면 안 됩니다.

### 2-5. 학생 계정 만들기

**앱에는 가입 기능이 없습니다.** 계정은 선생님이 만든 것만 존재합니다.
도시가 망했다고 계정을 새로 파서 다시 시작하는 걸 막기 위한 구조입니다.
도시 문서 ID 가 곧 로그인 UID 라서, 한 계정이 도시 둘을 가지는 것도 불가능합니다.

**방법 A — 콘솔에서 (권장, 20번 클릭)**
Authentication → Users → **사용자 추가**.
이메일은 `s01@cities19.local` … `s28@cities19.local` 형식,
비밀번호는 6자 이상. 학생은 앱에서 **번호(1)와 비밀번호**만 칩니다.
`1` 을 치면 코드가 알아서 `s01@cities19.local` 로 바꿉니다.

**방법 B — 앱에서 몰아서 (빠름)**
내 컴퓨터의 `.env` 에만 `VITE_ALLOW_SIGNUP=1` 을 넣고 `npm run dev` 를 돌리면
로그인 화면에 "계정 만들기" 버튼이 생깁니다. 번호를 바꿔가며 연달아 만들 수 있습니다.
**다 만들면 지우세요. Vercel 환경변수에는 절대 넣지 마세요.**
켜둔 채로 배포하면 학생이 계정을 무한정 만들 수 있습니다.

> 도메인(`cities19.local`)은 `VITE_STUDENT_DOMAIN` 으로 바꿀 수 있지만,
> **한 번 정하면 바꾸지 마세요.** 바꾸면 기존 계정으로 로그인이 안 됩니다.


`.env` 가 없으면 로그인 화면 대신 "서버 설정이 없어 저장 없이 둘러보기만 할 수

| 동작 | 터치(아이패드) | PC |
|---|---|---|

## 4. 저장이 어떻게 동작하나

### 무엇을 저장하나

지형과 고도는 **저장하지 않습니다.** `(좌표, WORLD_SEED)` 에서 항상 같은 값이
나오므로 접속할 때마다 다시 만듭니다. Firestore 에 들어가는 건 세 가지뿐입니다.

1. **생성값과 달라진 칸** — 학생이 고친 타일만
2. **개척한 청크 목록** — 안개를 걷은 곳
3. **도시 상태** — 이름, 도시 번호, 매크로(돈·인구·틱). 매크로는 3단계에서 채웁니다.

```
meta/registry                    도시 번호 발급기 (nextIndex 하나)
cities/{uid}                     도시 1개 = 계정 1개. 문서 ID 가 곧 로그인 UID
cities/{uid}/chunks/{cx}_{cy}    그 청크에서 달라진 칸 (압축 문자열)
```

문서 ID 를 UID 로 둔 덕분에 보안 규칙이 `request.auth.uid == cityId` 한 줄로
끝납니다. 규칙 안에서 다른 문서를 `get()` 하지 않으니 읽기 요금도 안 붙습니다.

### 얼마나 작아지나

청크 하나(4096칸)를 런렝스로 압축하고 base64 로 넣습니다. 실측입니다.

| 상황 | 저장 크기 |
|---|---|
| 한 칸도 안 고침 | 문서를 아예 안 만듦 |
| 5칸 고침 | 20자 |
| 8칸마다 도로를 깐 격자 | 3.5KB |
| 최악(모든 칸이 옆칸과 다름) | 16KB |

Firestore 문서 한도가 1MB 이니 최악이어도 1.6% 입니다.

### 언제 저장하나

Spark 무료 한도는 **하루 쓰기 2만 건**입니다. 5초마다 저장하면 학생 20명이
수업 두 시간 만에 한도를 넘깁니다. 그래서 두 겹으로 막습니다.

- 바뀐 게 있을 때만 저장합니다. 가만히 있으면 쓰기가 **0** 입니다.
- 마지막 변경 후 **5초** 조용하면 저장하고, 저장 간 간격은 최소 **60초** 입니다.
- 대신 **앱을 닫거나 탭을 옮기면 간격을 무시하고 즉시** 저장합니다.
  작업을 잃는 것보다 쓰기 한 건이 쌉니다.

두 손잡이는 `constants.ts` 의 `SAVE_DEBOUNCE_MS` 와 `SAVE_MIN_INTERVAL_MS` 입니다.

### 두 기기에서 동시에 켜면

학생이 학교 아이패드와 집 컴퓨터에서 같이 켜는 일이 생깁니다.
도시 문서에 `saveToken` 이 있고 **로그인할 때마다 새로 발급**됩니다.
저장할 때 토큰이 다르면 저장을 거부합니다.

**나중에 접속한 기기가 이깁니다.** 먼저 있던 기기는 화면 오른쪽 위에
"다른 기기에서 접속했습니다" 가 뜨고 그때부터 저장하지 않습니다.
두 기기가 서로를 덮어쓰며 왔다 갔다 하는 것보다 이쪽이 낫습니다.

### 서버가 죽으면

Firebase 설정이 없거나 불러오기가 실패해도 **게임은 뜹니다.**
저장만 꺼지고 0단계와 똑같이 지도를 돌아다닐 수 있습니다.
설정 실수로 학생들이 흰 화면을 보는 일은 없습니다.

### 성능에서 중요한 부분

타일 4,096개를 스프라이트 4,096개로 만들면 아이패드에서 청크 몇 개만 띄워도
프레임이 무너집니다. `chunkMesh.ts` 는 청크 하나를 **정점 버퍼 하나**로 구워서
**드로우콜 1회**로 그립니다. 타일 하나가 바뀌면 그 타일의 UV 8개만 고쳐 씁니다.
2단계에서 도로를 그을 때도 이 경로(`ChunkMesh.setTile`)만 타면 됩니다.
**이 구조를 스프라이트 방식으로 되돌리지 마세요.**

실측: 청크 하나당 사각형 약 5,600개(윗면 4,096 + 절벽 약 80 + 고도 음영 약 1,400),
정점 버퍼 약 360KB. 화면에는 보통 청크 10~25개가 올라갑니다.

## 6. 고도가 어떻게 동작하나

- 고도는 **0~8 단계**, 한 단계가 화면에서 16px 입니다.
- 지형 생성 함수가 고도를 함께 만듭니다. 저장하지 않고 좌표에서 매번 계산합니다.
- **이웃 타일 간 고도 차이는 항상 0 아니면 1 단계**입니다. 60만 개 지점을 검사해
  확인했습니다. 절벽은 한 칸씩 계단으로 올라가고, 산은 여러 타일에 걸쳐 층으로
  쌓입니다. 2단계의 도로 경사 판정은 이 성질에 기대면 됩니다.
- 절벽 옆면은 두 방향만 그립니다(오른쪽 아래 = +tx, 왼쪽 아래 = +ty).
  나머지 두 면은 카메라에서 안 보이므로 아예 만들지 않습니다.
- 고도가 높을수록 윗면을 살짝 밝게 덮습니다. 이 음영 칸은 **코드가 자동 생성**해
  아틀라스 뒤에 붙입니다 — 그림 작업 대상이 아닙니다.
- 물은 항상 고도 0 이고, 해안에서는 고도가 완만하게 올라옵니다(해안 절벽 방지).

넓은 영역 400만 지점 표본: 물 30%, 모래 9%, 풀·마른풀 41%, 숲 11%, 흙 3%,
바위산 5.5%. 고도는 0단계가 48%, 나머지가 1~8단계에 퍼집니다.

> **나중에 쓸 확장 지점**: 고도 음영과 똑같은 방식으로 아틀라스에 칸만 추가하면
> 영토 색, 오염 히트맵, 상하수도 커버리지 같은 타일 단위 색 오버레이를 셰이더
> 없이 그릴 수 있습니다. 6단계의 영토 표시는 이걸로 갑니다.

## 7. 그림 규격 (GPT 작업의 기준)

`public/sprites/terrain.png` 를 만들어 넣으면 코드가 자동으로 그걸 씁니다.
없으면 임시 타일이 자동 생성되므로 그림 없이도 게임은 돌아갑니다.
HUD 에 "그림: 임시 타일 사용 중" 이 뜨면 아직 임시 타일입니다.

- 전체 크기 **544 × 72 px** (가로 8칸 × 세로 2줄), PNG-32.
- **셀 크기 68 × 36 px.** 바깥 2px 은 반드시 완전 투명한 여백입니다(색 번짐 방지).

## 8. GPT 에게 넘길 작업

우선순위 순입니다. **1~4번은 코드를 고치는 게 아니라 콘솔·기기에서 확인하는 일**입니다.

1. **Firebase 세팅** — 위 2번 절차대로. 규칙 붙여넣기와 계정 만들기까지.
2. **처음 로그인 확인** — 로그인하면 Firestore 에 `cities/{uid}` 문서가 생기고
   `meta/registry` 의 `nextIndex` 가 1 올라가는지 콘솔에서 봅니다.
   두 계정으로 각각 로그인했을 때 `cityIndex` 가 0, 1 로 다르게 나와야 합니다.
   HUD 의 "도시" 줄에서도 번호가 보입니다.
3. **저장 왕복 확인** — 툴바의 **지형 칠하기**를 켜고 타일 몇 개를 탭한 뒤,
   오른쪽 위가 "저장됨" 이 될 때까지 기다립니다. 새로고침해서 그 타일이
   그대로 흙으로 남아 있으면 성공입니다.
   Firestore 에서 `cities/{uid}/chunks/...` 문서도 확인하세요.
   → 이게 되면 1단계의 목적은 다 이룬 겁니다.
4. **두 기기 충돌 확인** — 아이패드에서 켜둔 채 컴퓨터에서 같은 번호로 로그인한 뒤,
   아이패드에서 타일을 칠해 봅니다. "다른 기기에서 접속했습니다" 가 떠야 합니다.
5. **타일 그림 12칸** — 아직 임시 타일이면 7번 규격대로 `public/sprites/terrain.png` 제작.
6. **아이패드 실기기 확인** — 0단계 항목(핀치·드래그·탭)이 그대로 되는지.
   로그인 입력창을 눌렀을 때 사파리가 화면을 확대하면 안 됩니다
   (`.login-field input` 의 `font-size: 16px` 이 그걸 막고 있습니다).
7. **성능 재확인** — 최대 축소에서 fps. 0단계와 같아야 합니다.
   저장 로직은 렌더 루프 밖에 있으므로 프레임에 영향이 없어야 정상입니다.

### 손대면 안 되는 것

0단계 항목은 그대로입니다.

- `constants.ts` 의 `WORLD_SEED`, `TILE_W/H`, `HEIGHT_UNIT`, `CHUNK_SIZE` —
  바꾸면 이미 만든 도시가 전부 어긋납니다.
- `terrain.ts` 의 `hash2`, `valueNoise`, `fbm` — 서버(Vercel 함수)도 똑같은 값을
  계산해야 합니다. 여기서 `Math.random` 을 쓰거나 식을 고치면 지형이 갈라집니다.
- `iso.ts` 의 변환식 — 이 파일이 좌표계의 유일한 기준입니다.
- `chunkMesh.ts` 의 사각형 순서 — 절벽·윗면·음영의 순서가 곧 그리는 순서입니다.

1단계에서 추가된 것.

- **`cityIndex` 는 한 번 정해지면 절대 안 바뀝니다.** 코드로도, 콘솔에서 손으로도
  바꾸지 마세요. 바꾸면 그 학생의 도시가 지도 위에서 순간이동하고, 이미 다른
  학생이 쓰고 있는 자리와 겹칩니다. 보안 규칙에도 막아 두었습니다.
- **`meta/registry` 의 `nextIndex` 를 손으로 되돌리지 마세요.** 되돌리면 다음
  학생이 남의 자리를 배정받습니다.
- **`codec.ts` 의 압축 형식** — 바꾸면 이미 저장된 데이터를 못 읽습니다.
  꼭 바꿔야 하면 `SCHEMA_VERSION` 을 올리고 변환 코드를 넣으세요.
- **`OVERRIDE_NONE`(255)** — "안 바뀐 칸" 표시입니다. 지형 종류가 255가지가
  되는 일은 없으니 안전하지만, 이 값을 지형 ID 로 쓰면 안 됩니다.
- **`VITE_ALLOW_SIGNUP` 을 Vercel 에 넣지 마세요.** 학생이 계정을 무한정 만들 수
  있게 됩니다.
- **`VITE_STUDENT_DOMAIN`** — 바꾸면 기존 계정으로 로그인이 안 됩니다.

### 임시로 넣어둔 것

툴바의 **지형 칠하기** 버튼은 저장이 도는지 확인하려고 넣은 임시 기능입니다
(탭하면 흙으로 바뀝니다). 2단계에서 진짜 도로·지구 도구가 들어올 때 지웁니다.
`main.ts` 의 `painting` 변수와 `btn-paint` 만 지우면 됩니다.

## 9. 지금 일부러 빼둔 것

| 항목 | 언제 | 지금 상태 |
|---|---|---|
| 도로·지구 지정 | 2단계 | `World.setTile` 로 칠하기만 되고 규칙이 없음 |
| 건물·차량 스프라이트 레이어 | 2~4단계 | 지면 레이어만 있음 |
| 돈·인구·수요 | 3단계 | `macro` 필드가 0으로 자리만 잡혀 있음 |
| 서버 권한 검증 | 3단계 이후 | 지금은 학생이 자기 도시를 직접 씀. 규칙이 남의 도시만 막는다 |
| 오프라인 따라잡기 | 3단계 | `macro.tick`, `macro.tickedAt` 자리만 있음 |
| 지형 편집(터레이닝) | 미정 | `setHeight` 와 고도 오버레이 저장 경로까지는 뚫려 있음 |
| 안개 개척 | 5단계 | `World.explore()` 는 저장까지 되지만 개척 조건이 없음 |
| 전쟁·영토 | 6단계 | 없음 |

> **서버 권한 검증에 대해**: 지금은 학생이 자기 도시 문서를 직접 씁니다. 코드를
> 읽을 줄 아는 학생이 돈을 조작할 수 있다는 뜻입니다. 3단계에서 돈이 실제로
> 생기면 `macro` 만 Vercel 함수가 쓰도록 규칙을 조이면 됩니다.
> **경로는 그대로 두고 규칙만 바꾸면 되므로 데이터 이사는 필요 없습니다.**
