# 도시 게임 완성도 개선 — 작업 기록

## 사용자가 확정한 방향

- 테오타운처럼 읽기 쉬운 도트 그래픽. 건물·시설·도로·지형의 도트 크기, 투영, 명암을 일관되게 한다.
- 도시 운영의 깊이는 시티즈 수준 또는 그 이상을 지향한다. 비주얼과 실제 시뮬레이션의 인과관계를 함께 검증한다.
- 주거·상업·공업은 형태로 용도가 읽혀야 한다. 특수 시설은 특히 소방서·병원·항구 등이 멀리서도 구별되어야 한다.
- 전쟁·군사는 이번 범위에서 제외한다. 기능 세분화·경제·교통의 중요한 규칙 선택은 사용자에게 질문한다.
- 사용량에 맞춰 검증 가능한 묶음으로 진행하고 기록한다. 완료된 변경은 검사 → main 커밋 → origin/main 푸시 → SHA 일치 확인한다.
- 이전에 생성한 고해상도 건물 후보는 적용하지 않았다. 이를 단순 축소해 도트 밀도가 검증되었다고 주장하지 않는다.

## 현재 묶음 A — 도트 규격과 건물/시설 식별성

기준 main: `a73d9d4`. 시작 시 작업 트리 깨끗함.

- 구현: 40색·정수 픽셀·공통 투영으로 주상공 36종과 시설 26종을 제작했다. [제작 규격](PIXEL_ART_GUIDE.md).
- 타일 64×32, 기존 footprint/시설 ID/저장/경제 규칙 유지. 창문·문·층간 간격·나무·차량은 부지 크기에 비례 확대하지 않는다.
- 시설 찾기(종류별 개수·이전/다음·카메라 이동·부지 강조), 간결한 HUD와 접는 진단 정보, 화면 정리, 작은 화면에서 여닫는 도시 정보판을 추가했다.
- 일반 건물과 시설을 같은 깊이순으로 그려 뒤 공원이 앞 건물 지붕 위에 찍히던 오류를 수정했다. 경계 부지는 앞쪽 청크의 묶음에 넣어 도로가 병원의 앞부분을 덮던 오류도 수정했다.
- 탐색 상한 3×3 때문에 5×5·7×7 시설 끝부분을 선택/철거하지 못하던 오류를 고쳤다. 경계에 걸친 전체 부지와 철거 후 캐시 갱신도 검사했다.
- 실제 브라우저: 경계 병원 전후, 소방서/병원 위치 찾기, 없는 시설 버튼 비활성, 320px 정보판/미니맵/도구 간격과 화면 정리, 50% 시설 검수 확인. 서버 설정이 없는 로컬 환경이므로 클라우드 저장 업로드는 이번 브라우저 검증에 포함되지 않는다.

### 검증과 기존 실패

- 통과: `pixel visual infrastructure policies power water progression placement traffic lane disaster atlas special transport structure citygen` 개별 검사, 프로덕션 빌드.
- `check:parity`: 기존 메시 17사례 + 이번 수정 전 `a73d9d4` 대비 60일 매크로 이력·배정·저장 타일 계층 동등성 통과. 과거 STEP 3 기준은 이후 의도된 STEP 4 변경과 달라 기본 비교 기준을 이번 작업 직전으로 명시했다. `PARITY_BASELINE`으로 기준을 지정할 수 있다.
- 전체 `npm run check`는 아직 통과하지 않는다. 서비스 검사 23번의 서로 다른 날짜 입주율 비교(24.09%→24.08%)와 전기·수도·위생을 설치하지 않는 옛 220일 성장 시나리오(최종 25%, 기대 55~94%)가 실패한다. 두 실패 모두 `a73d9d4`의 실제 소스로 재실행해 동일하게 재현했다. 기대값을 낮추거나 실패를 무시하지 않았다.
- 전체 `format:check`에는 이번 수정 전부터 32개 파일의 포맷 차이가 남아 있다. 이번 수정 파일을 포맷하고 기존 파일 전체 재포맷은 분리한다.
- 로컬 상세 출력: `.check/full-check.log`, `.check/baseline-service.log`, `.check/baseline-sim.log`, `.check/polish-focused.log`, `.check/citygen-check.log`, `.check/polish-build.log`.
- 이 묶음은 비주얼 기반과 확인된 오류 수정의 체크포인트다. 도시 게임 전체 또는 테오타운 수준의 최종 아트가 완성된 것은 아니다.

## 묶음 B1 — 도시 진단과 시설 선택 가독성

- 입주율 한 값만 보고 변화 추세를 단정하거나 도로 문제로 잘못 안내하던 문구를 제거했다.
- 실제 도로 미연결 건물, 전력, 급수·하수, 수질 오염, 위생·장의, 서비스 커버, 과부하, 복지, 하루 수지를 우선순위로 안내한다. 한 화면에는 세 원인만 보여주고 나머지는 상세 지표로 연결한다.
- 복지 충족률의 단위를 주민 비율이 아닌 주거 건물 비율로 바로잡았다.
- 시설 설치창 26종 카드에 실제 도트 외형을 넣고, 공백을 무시하는 이름 검색과 빈 결과 안내를 추가했다. 시설을 고르면 선택창이 닫히고 배치 화면으로 돌아간다.
- 검사: `node tools/check/run.mjs advice`; 프로덕션 빌드 및 실제 브라우저에서 도시 진단, 공항 검색/잠금, 없는 결과, `소 방 서` 검색, 카드 선택 후 닫힘을 확인한다.

## 묶음 B2 — 도로·지구 표면 도트 통일

- 도로 16연결 상태의 브라우저 선·대시·그라데이션을 제거하고 정수 픽셀 노면, 골재, 연석, 방향별 황색 중심선으로 바꿨다.
- 도로가 끝나는 변은 밝은 연석, 세 갈래 이상은 어두운 중앙 포장으로 구별한다.
- 주거·상업·공업 지구에 각각 집·상점·공장 도형을 넣었다. 네 모서리의 짧은 눈금 밝기로 도로 접촉 상태를 구분하며, 화면을 뒤덮던 밝은 전체 테두리는 사용하지 않는다.
- 시설 바닥도 동일한 정수 픽셀 포장과 공공시설 표식을 사용한다. 저장 ID, 연결 마스크, 배치 규칙, 청크당 지형 메시 구조는 유지한다.
- 검수 페이지의 `도로·지구 24종` 탭에서 50%·100%·200%를 직접 비교할 수 있다. `node tools/check/run.mjs surface`는 도로 16 + 지구 6 + 시설 바닥 2상태가 불투명 정수 픽셀이며 100%와 최근접 50%에서 모두 서로 다른지 확인한다.

## 이후 묶음

1. 도로/지구/지형의 가독성, 시설 위치 찾기와 상태 표시, 실제 배치·철거·공급 장애 진단.
2. 입주·고용·통근·서비스·물류의 실제 원인과 UI 설명을 대조하고 확인된 오류를 회귀 테스트와 함께 수정.
3. 주상공 기능 세분화 및 경제/교통 고도화는 현행 구현을 정리한 구체안으로 질문 후 진행.
4. 장기 도시 운영·저장 복원·접근성·성능 점검. 미구현 항목을 완료로 표시하지 않는다.
