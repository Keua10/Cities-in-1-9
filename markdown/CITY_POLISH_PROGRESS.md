# 도시 게임 완성도 개선 — 작업 기록

## 사용자가 확정한 방향

- 테오타운처럼 읽기 쉬운 도트 그래픽. 건물·시설·도로·지형의 도트 크기, 투영, 명암을 일관되게 한다.
- 도시 운영의 깊이는 시티즈 수준 또는 그 이상을 지향한다. 비주얼과 실제 시뮬레이션의 인과관계를 함께 검증한다.
- 주거·상업·공업은 형태로 용도가 읽혀야 한다. 특수 시설은 특히 소방서·병원·항구 등이 멀리서도 구별되어야 한다.
- 전쟁·군사는 이번 범위에서 제외한다. 기능 세분화·경제·교통의 중요한 규칙 선택은 사용자에게 질문한다.
- 사용량에 맞춰 검증 가능한 묶음으로 진행하고 기록한다. 완료된 변경은 검사 → main 커밋 → origin/main 푸시 → SHA 일치 확인한다.
- 고해상도 생성물은 형태 참고 원본으로만 사용한다. 실제 게임에는 최근접 축소·팔레트 양자화·이진 알파 검사를 거친 64/128/192px 네이티브 파일만 넣고, 그 파일을 재생성 입력으로 고정한다.

## 현재 묶음 A — 도트 규격과 건물/시설 식별성

기준 main: `a73d9d4`. 시작 시 작업 트리 깨끗함.

- 구현: 40색·정수 픽셀·공통 투영으로 주상공 36종과 시설 26종을 제작했다. [제작 규격](PIXEL_ART_GUIDE.md).
- 타일 64×32, 기존 footprint/시설 ID/저장/경제 규칙 유지. 창문·문·층간 간격·나무·차량은 부지 크기에 비례 확대하지 않는다.
- 시설 찾기(종류별 개수·이전/다음·카메라 이동·부지 강조), 간결한 HUD와 접는 진단 정보, 화면 정리, 작은 화면에서 여닫는 도시 정보판을 추가했다.
- 일반 건물과 시설을 같은 깊이순으로 그려 뒤 공원이 앞 건물 지붕 위에 찍히던 오류를 수정했다. 경계 부지는 앞쪽 청크의 묶음에 넣어 도로가 병원의 앞부분을 덮던 오류도 수정했다.
- 탐색 상한 3×3 때문에 5×5·7×7 시설 끝부분을 선택/철거하지 못하던 오류를 고쳤다. 경계에 걸친 전체 부지와 철거 후 캐시 갱신도 검사했다.
- 실제 브라우저: 경계 병원 전후, 소방서/병원 위치 찾기, 없는 시설 버튼 비활성, 320px 정보판/미니맵/도구 간격과 화면 정리, 50% 시설 검수 확인. 서버 설정이 없는 로컬 환경이므로 클라우드 저장 업로드는 이번 브라우저 검증에 포함되지 않는다.

- 통과: `pixel visual infrastructure policies power water progression placement traffic lane disaster atlas special transport structure citygen` 개별 검사, 프로덕션 빌드.

- 전체 `format:check`에는 이번 수정 전부터 32개 파일의 포맷 차이가 남아 있다. 이번 수정 파일을 포맷하고 기존 파일 전체 재포맷은 분리한다.
- 로컬 상세 출력: `.check/full-check.log`, `.check/baseline-service.log`, `.check/baseline-sim.log`, `.check/polish-focused.log`, `.check/citygen-check.log`, `.check/polish-build.log`.
- 이 묶음은 비주얼 기반과 확인된 오류 수정의 체크포인트다. 도시 게임 전체 또는 테오타운 수준의 최종 아트가 완성된 것은 아니다.

## 묶음 B1 — 도시 진단과 시설 선택 가독성

- 입주율 한 값만 보고 변화 추세를 단정하거나 도로 문제로 잘못 안내하던 문구를 제거했다.
- 실제 도로 미연결 건물, 전력, 급수·하수, 수질 오염, 위생·장의, 서비스 커버, 과부하, 복지, 하루 수지를 우선순위로 안내한다. 한 화면에는 세 원인만 보여주고 나머지는 상세 지표로 연결한다.
- 복지 충족률의 단위를 주민 비율이 아닌 주거 건물 비율로 바로잡았다.
- 시설 설치창 26종 카드에 실제 도트 외형을 넣고, 공백을 무시하는 이름 검색과 빈 결과 안내를 추가했다. 시설을 고르면 선택창이 닫히고 배치 화면으로 돌아간다.
- 검사: `node tools/check/run.mjs advice`; 프로덕션 빌드 및 실제 브라우저에서 도시 진단, 공항 검색/잠금, 없는 결과, `소 방 서` 검색, 카드 선택 후 닫힘을 확인한다.

## 묶음 B2 — 도로·지구 표면 도트 통일

- 도로 16연결 상태의 브라우저 선·대시·그라데이션을 제거하고 정수 픽셀 노면, 골재, 연석, 방향별 황색 중심선으로 바꿨다.
- 도로가 끝나는 변은 밝은 연석, 세 갈래 이상은 어두운 중앙 포장으로 구별한다.
- 주거·상업·공업 지구에 각각 집·상점·공장 도형을 넣었다. 네 모서리의 짧은 눈금 밝기로 도로 접촉 상태를 구분하며, 화면을 뒤덮던 밝은 전체 테두리는 사용하지 않는다.
- 시설 바닥도 동일한 정수 픽셀 포장과 공공시설 표식을 사용한다. 저장 ID, 연결 마스크, 배치 규칙, 청크당 지형 메시 구조는 유지한다.
- 검수 페이지의 `도로·지구 24종` 탭에서 50%·100%·200%를 직접 비교할 수 있다. `node tools/check/run.mjs surface`는 도로 16 + 지구 6 + 시설 바닥 2상태의 마름모 안쪽이 불투명하고 바깥쪽이 투명하며, 100%와 최근접 50%에서 모두 서로 다른지 확인한다.

## 묶음 B4 — 주상공 36종 완성 픽셀 아틀라스

- 승인된 A/B 18종에 C/D 18종을 추가했다. 주거는 텃밭·타운하우스·놀이터 아파트·중정 단지·옥상정원, 상업은 편의점·식당·슈퍼마켓·복합상가·백화점·호텔, 공업은 정비소·작업장·물류·식품 가공·광역 물류·정밀 전자 생산으로 소품과 실루엣을 달리했다.
- 신규 C/D는 64/128/192px에서 각각 제작 규격을 고정한다. 색 채널을 32단계 도트 팔레트로 양자화하고 알파를 0/255로 고정했으며, 좌우·위·아래에 투명 여백을 둬 나무·차량·탱크·안테나가 셀 경계에서 잘리지 않게 했다.
- 바닥 마지막 불투명 행의 중심 오차는 0~0.5px다. 최종 C/D PNG를 제작 원본에 다시 저장하고 재생성 결과와 RGBA를 전수 비교하므로 고해상도 중간 파일이나 보간 결과가 다시 섞이지 않는다.
- `public/sprites/buildings-v2.png`는 2304×384 단일 아틀라스에 36개 네이티브 셀을 최근접 보간 없이 배치한다. 게임 로더는 이 파일을 사용하고, 파일 로드 실패 때만 이전 코드 도형으로 대체한다.
- 검수 페이지의 `주거/상업/공업 12종`은 실제 적용 픽셀을 표시한다. `완성 픽셀 비교 L1/L2/L3 12종`은 이전 코드 도형과 A~D 최종본을 50%·100%·200%로 비교한다.
- `npm run art:buildings`가 신규 후보와 아틀라스를 재현한다. `node tools/check/run.mjs candidate variants`는 36종의 해상도·이진 알파·투명 여백·중앙 바닥·서로 다른 래스터, C/D 원본의 무보간 동일성, 아틀라스 전 픽셀과 빈 영역 투명도를 검사한다.

## 이후 묶음

### B5 1차 — 청크 경계의 지형/건물 가림 수정

- 사용자 스크린샷 후 기존의 "정상 적용" 판정을 철회했다. PNG의 네 변 투명 여백 검사는 실제 지형과의 합성 검사가 아니었다. `terrainBuildingsVisual.html`의 평지/경사/앞쪽 높은 지형 장면으로 경계를 재현했다.
- 기존 렌더러는 64×64 청크의 지면 전체 → 해당 청크 건물 전체 → 다음 청크 지면 순서였다. 다음 청크의 뒤쪽 도로·잔디가 이미 그린 건물에 덮여 삼각형으로 잘리는 문제가 있었다.
- `TerrainStructureScene`에서 지면·절벽·경사도로·일반 건물·시설을 전역 타일 깊이순으로 합성한다. 저장 청크 경계와 그리기 순서를 분리하고, 같은 깊이에서는 지면을 먼저 그린다. 앞쪽 높은 지형에 의한 실제 가림은 유지한다.
- 도로 램프와 절벽 정점은 기존 `ChunkMesh` 값을 그대로 사용한다. 경사면 계산식과 도로 연결/고도/저장 데이터는 변경하지 않았다. 신규 건물 PNG 하단의 1px 투명 여백을 배치 좌표에 반영하고 보행자 가림 좌표도 함께 맞췄다.
- 정적 장면은 합성 메시 1개로 보관하고, 청크/건물/고도/도로 UV 변경 또는 가시 청크 교체 때만 재합성한다. 공급 범위 모드는 지면 투명도를 유지하면서 건물만 낮춘다.
- 검증: `terrainScene visual variants pick placement` 및 프로덕션 빌드 통과. 새 검사는 전역 순서, 경계를 넘는 시설 전 부지, 앞쪽 지형 가림, 경사도로·절벽 정점 보존, 경사 접합 연속성, 바닥 기준점, 120프레임 캐시 재사용, 도로 1칸 UV 변경, 공급 범위 알파, 빈 화면 정리를 포함한다. 브라우저 3개 재현 장면과 오프라인 도시 화면 확인. 재현 장면의 최초 합성 약 10ms, 정지 화면 추가 합성 0회(이 PC에서의 관측값).
- **남은 2차:** 차량은 여전히 별도 동적 레이어로 그려진다. 뒤쪽 도로 차량이 앞 건물 지붕 위로 올라오는 가림 문제는 아직 해결되지 않았다. 다음 작업은 차량/건물/경사도로의 동적 가림과 픽셀 부지의 세부 정렬을 전용 재현 장면에서 검사한다. 이번 변경을 모든 그래픽 문제 해결로 표시하지 않는다.

### B5 2차 — 차량/건물 가림과 차체의 타일 경계 잘림

- 직진 차량은 청크 위, 회전 차량은 지형/건물 전체 위에 그리던 별도 레이어를 제거했다. 두 종류 모두 전역 깊이 합성에 참여한다. 뒤쪽 차는 건물의 불투명 부분에 가려지고, 투명한 부분과 앞쪽 차는 보인다.
- 1차의 단일 정적 메시를 타일 깊이별 메시로 나눴다. 지면/건물/차량이 같은 아틀라스를 공유하고 Pixi 배칭을 사용한다. 정적 지형은 계속 캐시하며 차량 버퍼만 갱신한다. 공급 범위 모드에서도 지면과 차량의 불투명도는 유지한다.
- 차량 중심 타일만 사용한 중간 구현에서는 다음 도로 타일이 차체 끝을 덮는 문제가 재현됐다. 실제 차량 래스터의 불투명한 전방 윤곽을 셀별로 캐시해 그 윤곽이 걸친 타일까지 깊이에 포함한다. 투명 여백은 제외하며 위치/크기/차선/높이는 기존 투영식을 사용한다.
- `vehicleScene` 신규 검사: 부분 가림과 앞쪽 차량 노출, 네이티브 승용차/트럭 3,600프레임의 평지 경계에서 차체가 지면에 덮이는 픽셀 0개, 양방향 경사 및 회전의 노면 접지, 120프레임 정적 캐시 보존, 차량 아틀라스 연결 후 UV 갱신, 공급 범위 알파, 1,000대 버퍼 용량, 차량 감소 및 빈 화면 정리.
- `terrainScene`을 새 깊이 메시 구조에 맞춰 수정했다. 기존 지형/절벽/램프 정점과 건물 바닥 1px 여백 보정 검사는 유지한다. `vehicleScene terrainScene lane visual pick placement` 및 프로덕션 빌드 통과. 기존 번들 크기 경고는 남아 있다.
- 실제 브라우저에서 평지/경사/앞쪽 높은 지형 장면에 양방향 이동 차량을 추가해 확인했다. 관측된 최초 합성은 약 13~25ms이고 이동 중 합성 횟수는 1회로 유지됐다. 이는 이 PC의 검수 장면 관측이며 대규모 도시 전체 성능 보장은 아니다.
- **다음 검수 범위:** PNG 내부 바닥의 실제 마름모 모양과 배치 부지 일치 여부, 건물별 크기 인상, 경사 지형에서 기초부 표현. 기존 중앙점/투명 여백 검사는 이 항목들의 완전한 검증이 아니다. 앞쪽 높은 땅에 실제로 가려지는 부분까지 제거하지 않으며, 도시의 모든 비주얼 문제를 해결했다고 표시하지 않는다.

### B5 4차 — 승인한 저택 v2와 주상공 전체 36종 바닥 규격 보정

- 사용자가 저택 v2의 느낌을 승인하고 나머지 전체의 색감·질감을 유지하며 규격을 맞추도록 요청했다. 승인 저택은 픽셀을 그대로 적용했다. 온전한 원본 30종은 양쪽 전면 바닥선을 각각 측정해 2:1로 투영하고 최근접 픽셀을 복사했다. 색 보간·채도 변경·그림 재생성은 하지 않았다. 이 과정은 픽셀 행을 재표본화하므로 원본의 모든 픽셀 개수나 건물 높이를 그대로 유지하는 방식은 아니며, 3D 재구성으로 표기하지 않는다.
- 전수 측정에서 L2 주거 A/B, 상업 A/B, 공업 A의 기존 원본 하단이 51~56px 길이로 잘린 것을 발견했다. 이 5종은 내장 image_gen으로 완전한 부지와 누락된 소품을 복원하고 각 원본의 실제 RGB 팔레트와 재질별 밝기 분포로 다시 맞췄다. 없는 원본 픽셀을 복구한 부분은 새로 그려진 부분이며, 원본 RGBA의 완전 보존으로 주장하지 않는다. 고해상도 출력은 투명 배경 분리와 최근접 축소를 거친 뒤 `tools/art/footprint-repairs/`에 128px 제작 입력으로 보관했다. 프롬프트와 처리 기록은 `tools/art/building-review/footprint-repair-prompts.json`에 있다.
- 최종 36종은 `public/sprites/aligned/`에 원본과 분리했다. 원본 `candidates/`와 승인 저택 v2는 그대로 남긴다. 작은 부지의 정원·보도 여백을 유지하고, 뒤쪽 투명 공간에 밋밋한 바닥 삼각형을 채우지 않는다. 전면의 좁은 테두리만 원본 바닥 픽셀로 보완한다.

- 검증: `footprints candidate variants terrainScene vehicleScene visual pixel` 검사 및 프로덕션 빌드 통과. 기존 번들 크기 경고는 유지된다. 새 결과가 재생성 후 원본 후보로 돌아가지 않는지도 해시로 확인한다.

### B6 특수시설 26종 — 상세 도트 제작 및 게임 적용

### B7 시설 위치 찾기 표식 — 선택 지점의 도트 핀과 맥동 링

- 기존 시설 찾기는 선택 시설의 부지 외곽선만 표시해 큰 시설이나 복잡한 도시에선 위치를 놓치기 쉬웠다. 선택한 한 곳에 어두운 외곽선, 금색 부지선, 중심 핀, 짧은 연결선, 도트풍 맥동 링을 함께 그려 멀리서도 찾을 수 있게 했다.
- 표식은 시설 아틀라스나 부지 픽셀을 수정하지 않고 별도 Graphics 레이어에서만 갱신한다. 확대 배율에 맞춰 선 두께를 보정하며 선택이 해제되면 즉시 비운다. 기존 카메라 이동·이전/다음 위치·철거 후 목록 정리 규칙은 유지한다.
- `npx tsc --noEmit` 통과. Vite/esbuild 검사는 현재 관리형 실행 환경의 프로젝트 경로 접근 제한으로 재실행이 차단되어, 통과로 표시하지 않는다. 다음 검수에서 실제 브라우저 화면의 시설 찾기 표식 크기와 경사 부지 겹침을 확인한다.

### B8 테오타운식 하단 건설 분류와 3터치 흐름

- 하단 건설 도구를 `선택 · 도로 · 구역 · 시설 · 서비스 · 교통 · 철거`의 7개 상위 분류로 정리했다. 주거·상업·공업은 `구역`, 배관·전선은 `서비스`, 활주로·유도로는 `교통` 안에 넣어 화면을 덮던 12개 평면 버튼을 줄였다.
- 구역·서비스·교통은 상위 분류를 한 번 누르면 같은 하단 막대 안에 세부 도구가 펼쳐진다. `분류 → 세부 도구 → 지도 배치`로 끝나며, 시설은 `시설 → 시설 카드 → 지도 배치`로 끝난다. 기존 드래그 설치와 비용·잠금·배치 규칙은 바꾸지 않았다.
- 서비스와 교통 메뉴는 세부 도구를 선택한 뒤에도 열린 상태를 유지해 같은 계열을 연속으로 바꿀 수 있다. 시설 카드는 공공 서비스·공원·복지·상하수도·발전·환경·특수·교통으로 짧게 묶어 읽기 순서를 맞췄다.
- 게임의 어두운 배경과 승인된 도트 팔레트에 맞춰 상위 도구마다 도로·구역·시설·서비스·교통·철거의 낮은 채도 강조색을 부여했다. 새 아이콘 이미지나 건물 텍스처는 추가하지 않았다.
- `npx tsc --noEmit`, 관련 파일 Prettier, `git diff --check` 통과. 실제 터치 순서와 반응형 폭은 브라우저 사용량 제한 해제 후 검수한다.

### B9 모바일 하단 패널과 시설 카드 밀도 조정

- 560px 이하 화면에서 하단 상위 도구를 가로 스크롤하지 않고 4열로 배치한다. 구역·서비스·교통 하위 도구도 같은 패널 안에서 줄바꿈되므로 분류 버튼을 찾기 위해 화면을 밀 필요가 없다.
- 시설 선택 패널에 `시설 선택 · 카드 선택 후 지도에 배치` 안내를 추가하고, 공공·복지·상하수도·발전·환경·특수 그룹 라벨에 게임 팔레트의 낮은 채도 색을 적용했다. 카드 폭을 줄여 한 화면에 더 많은 시설을 보여주되 상세 비용·용량·해금 정보는 유지한다.
- `npx tsc --noEmit`, 관련 파일 Prettier, `git diff --check` 통과. 브라우저의 320px·560px 실제 터치 검수는 사용량 제한 해제 후 진행한다.

### B10 테오타운식 가장자리 UI 재구성

- 사용자가 제공한 테오타운·시티즈 화면을 기준으로 기존의 화면을 덮는 좌측 정보창과 두 줄 하단 텍스트 메뉴를 제거하고, 얇은 상단 도시 상태줄·좌측 건설 레일·우측 정보 레일·하단 시간/재정줄·우측 하단 미니맵으로 재배치했다. 지도는 기본 상태에서 최대한 넓게 보이며 패널은 버튼을 눌렀을 때만 열린다.
- 건설 레일은 선택·구역·교통·전기·수도·공공·공원·환경·철거의 9개 버튼으로 고정했다. `분류 → 항목 → 지도` 세 번 안에서 끝나고, 검색은 분류를 세분화하지 않고 37개 항목을 직접 찾는다. 주거·상업·공업은 집·상점·공장 도트 아이콘을 별도로 사용하며 특수시설은 실제 시설 아틀라스 썸네일과 비용·유지비·용량·해금 레벨을 표시한다.
- 지도에서 건물을 한 번 누르면 건물 정보 패널이 열리고, 공항·항구는 기존 운영 패널을 사용한다. 우측 레이어 패널은 상수도·하수도·전력 오버레이를 각각 바로 켜며, 시간은 정지·1배·2배로 하단에서 조작한다. 패널이 열리면 다른 패널과 건설 브러시는 닫혀 중첩 입력을 막는다.
- 일시정지 중에는 공급망 상태만 갱신하고 틱·돈·입주를 진행하지 않는다. 저장 후 재접속할 때도 일시정지 시간이 오프라인 따라잡기로 변하지 않도록 `tickedAt`을 갱신한다.
- `gameUi` 집중 검사는 37개 항목의 중복·시설 비용/해금 일치, 정지·저장·재개, 1배/2배 진행을 확인한다. `placement`·`transport` 집중 검사와 `tsc --noEmit`, Prettier, `git diff --check`도 통과했다. 프로덕션 번들은 마지막 실행에서 관리형 실행 환경의 Vite 경로 접근 제한으로 실패했으며 타입 검사는 그 전에 통과했다. 브라우저 자동 재검수는 사용량 제한으로 차단되어 수동 검수 완료로 주장하지 않는다.

- 2026-09-15 푸시 전 재검증: 관리형 실행 제한이 해제되어 `npm run build`(타입 검사 포함)가 통과했다. 기존 Pixi 번들의 500kB 경고만 남았다. 이번 재검증은 프로덕션 빌드이며 브라우저 최종 재검수를 완료했다는 의미는 아니다.
