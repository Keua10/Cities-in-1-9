# 도시 게임 작업 묶음 — 2026-09-15

사용자 요청: 한 번에 구현하지 않고 묶음별 검증·푸시. 아래 기능을 마친 뒤 본격적인 경제·운영 밸런스를 조정한다. 실행 한도를 보장하거나 임의로 자동 초기화하지 않는다.

## 1차: 미니맵 입력과 관리자 도구

- 작은 지도 탭은 큰 지도를 열고 드래그는 해당 지도 위치로 카메라를 이동한다. 7 CSS px 이상 이동하면 드래그이며 시작점 복귀 시에도 탭으로 바뀌지 않는다. 포인터 캡처로 지도 밖 이동·손 떼기를 처리하며 취소·두 번째 포인터는 확대로 이어지지 않는다.
- 설정 → 관리자 코드 → `omelet9900`. 페이지 세션 내에서만 해제 상태를 유지한다. 현재 도시 자금의 절대값 설정 및 기존 대도시 재생성 기능을 제공한다. 대도시 생성은 기존 도시를 덮어쓰므로 확인창을 거친다.
- 자금은 0~1조 정수만 허용한다. 코드 게이트는 클라이언트 게임 도구 잠금이며 서버 관리자 인증이 아니다. 둘러보기 모드는 저장하지 않음을 표시한다. 서버 저장 오류나 충돌을 성공으로 안내하지 않는다.
- `minimapPointer` 검사가 탭·드래그·원점 복귀·취소·캡처 손실·두 번째 포인터·큰 지도 입력을 확인한다. 실제 브라우저에서 오답/정답 코드, 음수/소수/상한 초과 거부, 0 및 123456789 적용을 확인했다. 생성 확인창은 표시됐으나 브라우저 제어가 응답하지 않아 확인창 이후 생성·취소의 실브라우저 검증은 미완료다. `citygen`으로 기존 생성 알고리즘을 검증한다.

## 2차: 화폐 단위·가격 규모 조정

- 기존 저장/시뮬레이션 1단위를 10,000원으로 환산한다. 구역 지정 8 → 8만 원, 도로 12 → 12만 원, 생성 도시 자금 300,000 → 30억 원. 자금·건설비·시설 유지비·세입·지출·적자 안내를 같은 환산기로 표시한다.
- 원본 저장값은 변환하지 않으므로 예전 도시가 가진 구매력과 비용/수입 비율은 유지된다. 재접속 시 이중 환산도 없다. 일일 결산의 반올림 정밀도는 새 원 단위까지 보존한다.
- 카드와 하단 상태줄은 만·억·조 단위로 표시하고, 재정 상세창은 정확한 원 단위 금액을 보여준다. 관리자 입력도 원 단위이며 적용할 때 저장 단위로 역환산한다. 하단 수지는 재정 상세창과 같은 예상 수입/지출을 사용한다.
- `money` 검사는 관리자 원 단위 왕복, 8만 원 실제 차감, 기존 저장 불변·재불러오기·구매력 보존과 일일 결산 정밀도를 확인한다. `gameUi`, `advice`와 프로덕션 빌드도 검증한다. 실제 브라우저에서 8만 원 구역, 4,500만 원 소방서와 유지비, 관리자 123456789원 입력 후 재정창/상태줄의 정확한 금액 일치를 확인했다.

## 3차: 설정창 오류 및 신호등·보행자·차량 도트 개선

- 설정창의 `.game-ui .game-panel`보다 기존 `#toolbar`의 CSS 우선순위가 높아, 중앙 배치·가로 flex·하단 고정이 남았다. 설정/레이어 패널에 ID가 포함된 스타일을 명시해 오른쪽 세로 패널로 복구했다. 2560×1440, 1280×720, 390×844, 844×390에서 가로 넘침 0, transform 없음, 정상 위치를 브라우저에서 확인했다.
- 차량 신호등을 기둥·하우징·세 개 램프의 정수 픽셀 도형으로 교체했다. 실제 차량 판정과 같은 `signalState` 및 `signalTimeMs`를 사용한다. 보행자 신호등은 이번 묶음에 추가하지 않았다.
- 보행자는 원/타원과 소수 좌표 신체 대신 머리카락·피부·상의·팔·신발을 가진 정수 픽셀 실루엣 및 두 보행 자세로 바꿨다. 기존 경로·건물 알파 가림을 유지하고 새 머리 높이를 가림 검사에 포함했다.
- 승용차/트럭 × 4방향 × 4색의 32셀 도트 차량을 `vehicles-pixel.png`로 적용했다. 기존 코드 기반 차체 투영을 정수 스캔라인으로 그려 안티앨리어싱을 제거하고 측면 창문·바퀴·휠을 보강했다. `node tools/buildPixelVehicles.mjs`로 재생성한다. 셀은 32×32, 전체 512×64, RGBA 알파 0/255이며 모든 셀 외곽은 투명하다.
- `movingPixel vehicleScene placement traffic` 및 프로덕션 빌드 통과. 3,600프레임 평지 차량 가림 0, 경사 양방향/회전, 차량 감소/빈 장면, 1,000대 버퍼, 보행자 가림, 적신호/황색/전적색/양보/정지 후 우회전 검사를 포함한다. 실제 게임에서 새 차량·신호등과 설정창을 확인했다.

## 4차: 신호 체계 재구성 및 보행 방향 — 2026-09-16

- 기둥은 진입 차선 오른쪽 도로 가장자리에 두고, 돌출 팔이 차선 안쪽으로 뻗는다. 실제 지면 높이를 사용한다. 신호등 픽셀은 앞쪽 건물/시설의 불투명 픽셀에만 가려지며 투명 여백과 앞쪽 신호는 보존한다.
- 자동 신호는 넓은 도로 교차로 또는 10칸 이상 이어지는 진입로가 3개 이상인 교차로를 후보로 삼는다. 진입로 길이는 다음 교차로 앞에서 끊어 측정한다. 후보 사이 최소 맨해튼 거리 14칸, 넓은 교차로 우선이다. 짧은 주거 블록은 기존 무신호 양보/통행권을 사용한다.
- 교통 → 신호등 설치/제거 → 도로 탭으로 3회 이내 접근한다. 두 도구는 탭 설치, 드래그 지도 이동이다. 다중 타일 교차로는 한 영역으로 제어하며 다른 칸에서 재설치해도 이전 제거 지정을 해제한다. 직선 도로에도 수동 설치 가능하다. 제거한 교차로는 자동 설치에서 제외되고 저장 후에도 유지된다. 도로 철거와 도시 초기화 시 설정을 정리한다.
- 무작위 위상을 없애고 타일 간 이동 시간에 따른 순차 점등을 기본으로 한다. 1초마다 관찰한 차량 수/대기량을 1분 단위로 집계하고, 이동평균 및 방향 변경 임계값을 적용한다. 공통 주기는 유지하며 주기 경계에서 위상 최대 200ms, 녹색 배분 최대 500ms씩 조정한다. 각 축 녹색 최소 4.5초, 황색/전적색 순서와 기존 충돌 방지 규칙은 유지한다. 활성 지역의 우세 방향을 기준으로 하므로 모든 양방향·임의 도로망의 무정체를 보장하는 최적화는 아니다.
- 보행자는 실제 경로 선분과 왕복 상태에 따라 네 방향의 얼굴/뒷머리를 표시한다. 꺾이는 지점과 되돌아가는 지점을 회귀 검사한다.
- `signalPolicy movingPixel gameUi traffic placement vehicleScene` 및 프로덕션 빌드 통과. 4차로 격자 16개 교차로 중 자동 신호 7곳, 최대 동시 156대 시험에서 차체 겹침/무단 적신호 진입/충돌 궤적 동시 진입 0, 적신호 우회전 62회 모두 정지 후 진행. 건물 알파 가림의 앞/뒤/투명 여백 검사를 포함한다.
- 실제 브라우저 게임에서 교통 메뉴 → 도로 클릭 설치 및 같은 도로 제거를 확인했다. `tools/check/signalsVisual.html`은 실제 렌더러로 도로변 팔·앞쪽 건물 가림·정지 중 설치/제거·왕복 보행을 재현한다. 서버 로그인 저장은 실행하지 않았고 설정 직렬화/복원은 집중 검사로 확인했다.
