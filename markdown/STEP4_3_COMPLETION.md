# STEP 4.3 — 전력, 기반시설을 갖춘 대도시 생성, 공급 범위 표시

기준: main `66b3049` (STEP 4.2). 사용자 요청 범위인 STEP 4.3과 대도시 생성·유틸리티 보기를 함께 구현했다. STEP 4.4는 시작하지 않았다. 기존 STEP4_2_COMPLETION.md의 배관 도달 거리와 보기 설명은 이 문서의 변경 사항이 우선한다.

## 전력 규칙과 시설

| 시설 | kind / 저장 코드 | 도시 레벨 | 출력 | 건설비 | 하루 유지비 |
| --- | --- | ---: | ---: | ---: | ---: |
| 풍력발전소 | 11 / 20 | 1 | 2,000 | 5,000 | 100 |
| 가스발전소 | 12 / 21 | 2 | 12,000 | 18,000 | 650 |
| 태양광발전소 | 13 / 22 | 3 | 6,000 | 22,000 | 180 |

- 발전소는 도로에 접해야 가동한다. 출력은 초기 밸런스의 고정값이며 태양광도 평균 출력을 사용한다. 날씨·일조량·연료 시스템은 이번 범위에 없다.
- 전선은 상하좌우로 이어진다. 건물은 부지의 어느 칸에서든 맨해튼 거리 3 이내의 전선·다른 건물과 전력을 공유한다. 일직선에서는 빈 칸 2개까지 건너뛸 수 있다.
- 가까운 건물이 연결되면 그 건물에서도 다시 전력을 전달한다. **빈 땅에 표시된 공급 범위 자체는 전력을 중계하지 않는다.** 공원·소공원은 전력을 소비하거나 중계하지 않는다. 체육시설과 다른 공공시설은 참여한다.
- 연결망마다 발전량과 건물 수요를 한 번씩 합산한다. 수요 초과 시 같은 연결망의 공급률이 비례해서 감소한다. 발전원이 없는 고립망에는 전력이 공급되지 않는다.
- 전선은 칸당 건설비 18, 하루 유지비 0.08이다. 전선 철거는 지상 건물·도로와 배관을 보존한다.
- 상하수도 시설의 처리 용량과 공공서비스 품질은 전력 공급률에 따라 감소한다. 발전소는 물을 요구하지 않아 초기 가동의 순환 의존성을 피한다.
- 직접적인 정전 만족도 감점은 전력 도입 후 30일 유예, 다음 30일 점진 적용이며 인구 유예도 적용한다. 상하수도 시설·서비스의 실제 가동 저하는 즉시 적용된다.

## 설치 중 보기

- 상수도관·하수도관·전선 설치/철거 도구나 해당 시설을 선택하면 자동으로 해당 공급 보기를 켠다. 일반 도구로 돌아가면 원래 불투명도로 복원된다.
- ‘공급 범위 보기’ 버튼은 끄기 → 급수 → 하수 → 전력 순으로 순환한다.
- 일반 건물은 불투명도 20%, 시설은 25%로 표시하고 지형은 유지한다. 관·전선에는 어두운 외곽선을 넣어 구별하기 쉽게 했다. 건물끼리 전력을 공유하는 연결은 실제 전선보다 가는 선으로 표시한다.
- 급수는 파랑, 하수는 갈색, 전력은 노랑, 공급 부족은 주황, 오염수는 빨강, 비가동 관·전선은 회색이다. 탐사된 화면 영역만 그린다.
- 배관 공급 범위를 맨해튼 거리 4로 확장했다. 건물 부지 전체를 판정하며 **범위 색상과 실제 공급 판정은 같은 계산 결과를 사용한다.** 물이 공급되지 않는 관 주변은 공급 범위로 칠하지 않는다.
- 서로 다른 관이 겹치거나 상하좌우로 접하면 오염되는 기존 규칙은 유지한다. 공급 범위 색이 겹치는 것만으로는 오염되지 않는다.
- 도시 상태판에 전력 공급률·수요·발전량·미공급 건물 수를 추가했다. 건물 상세에는 전력 충족률, 기반시설 상세에는 전력 수요와 가동 상태를 표시한다.

## 대도시 생성

- 새 대도시 생성 및 맵 초기화 시 전력·상하수도를 함께 배치한다. 기존 저장 도시를 자동으로 초기화하거나 기존 건물을 재배치하지 않는다.
- 기존 도로 옆의 평탄한 육지를 찾아 발전소·지하수 펌프·하수처리장을 설치한다. 신규 도시의 일부 구역 건물은 기반시설 부지로 대체할 수 있다. 기존 도로와 공공시설은 보존한다.
- 건물 수요에 급수·하수 15%, 전력 25%의 여유를 두고 필요한 시설 수를 정한다. 전력 계산에는 공공시설 및 상하수도 시설 수요도 포함한다.
- 상수·하수는 반대쪽 주간선과 엇갈린 가지관으로 분리해 물리적으로 닿지 않게 했다. 전선망과 건물 간 자동 공유를 함께 사용한다.
- 내륙 하수처리장은 주변 빈 칸에 작은 방류 수로를 준비한다. 이는 기존 국소 수질 모델을 위한 배치이며 하천 유량 시뮬레이션은 아니다.
- 도시 0·1·7 생성 검사에서 전력·급수·하수 모두 100%, 오염수 공급 0채를 확인했다. 도시 0의 초기 값은 전력 48,000 / 수요 31,746, 급수 28,000·하수 30,000 / 수요 23,206이다. 성장 이후 값은 달라질 수 있다.

## 저장 호환성과 검증

- 전선은 청크의 선택 필드 `wires`로 저장한다. 1은 설치, 255는 제거이며 필드가 없는 기존 저장은 전선 없음으로 읽는다. 전선만 있는 청크도 저장·언로드·복구한다.
- 기존 시설 코드는 유지하고 새 발전소 코드 20~22만 추가했다. 전력 도입 시점은 선택 메타데이터 `powerStartTick`에 기록한다.
- `node tools/check/run.mjs power water atlas progression` 통과. 마지막 기능 수정 후 `power water`를 다시 실행해 통과했다.
- 핵심 검사는 건물 연쇄 공유·거리 경계·빈 땅의 비중계·중간 건물 철거/재설치·전선 연결·발전소 도로 단절·용량 부족·전력에 따른 급수량·전선 청크 저장 및 초기화·세 도시 생성 공급 상태를 다룬다.
- 최종 `npm run build`와 `git diff --check` 통과. 브라우저에서 배관/전선 모드의 반투명 처리와 색상·연결선 표시를 확인했다.
- 사용자 요청에 따라 전체 교통 회귀 검사, 장시간 밸런스 검사, 실제 Firebase 서버 저장 왕복 검사는 수행하지 않았다. 저장 구조는 로컬 검사로 확인했다.

다음 구현 범위는 STEP 4.4이며, 상세 검증과 밸런스 조정은 이 문서를 기준으로 이어갈 수 있다.
