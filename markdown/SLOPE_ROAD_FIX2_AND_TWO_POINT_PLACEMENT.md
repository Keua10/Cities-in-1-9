# 경사 도로 재수정 + 두 점 건설

작업 날짜 2026-09-19 · 브랜치 `fix-slope-road-and-two-point-placement`

두 가지를 고쳤다. 하나는 "비탈 도로가 지형을 기울여 보이게 한다", 다른 하나는
"드래그 건설이 되돌릴 수 없다" 다.

---

## 1. 경사 도로 — 지형이 아니라 도로가 움직인다

### 무엇이 틀렸나

`SLOPE_ROAD_NOTES.md` 의 규칙은 **"맞닿은 두 도로 타일의 변 높이 = 두 고도의 평균"**
이었다. 비탈 한 단계를 두 칸이 반씩 나눠 지는 방식이다.

```
고도 0 도로  [0 → 0.5]  고도 1 도로  [0.5 → 1]
```

도로면은 확실히 이어졌지만, **언덕 위의 평평해야 할 칸까지 반 칸 내려앉았다.**
화면에서는 도로가 오르막을 지는 게 아니라 **지형 자체가 기운 것처럼** 보인다.
언덕 꼭대기에 있어야 할 땅이 도로 때문에 주저앉기 때문이다.

### 지금 규칙 — 램프는 낮은 칸 하나가 통째로 진다

```
낮은 도로 칸   아래쪽 변 = 자기 고도 h,  위쪽 변 = h + 1   (한 칸 안에서 한 단계)
높은 도로 칸   언제나 자기 고도로 평평하다
도로가 아닌 칸 언제나 평평하다. 절벽도 그대로 남는다
```

테오타운의 비탈 도로, 마인크래프트의 오르막 레일과 같은 모형이다. **지형은 절대
기울지 않고**, 더 높은 도로와 이으려고 낮은 쪽 도로가 몸을 일으킨다.

0-1-2 로 이어지는 곧은 비탈길은 칸마다 한 단계씩 올라 그대로 이어진다. 고도 0 칸의
위쪽 변(=1)과 고도 1 칸의 아래쪽 변(=1)이 정확히 만나므로 틈이 없다.

한 칸이 **두 방향으로 올라가야 하는** 그릇 바닥은 평면 하나로 그릴 수 없다.
`canConnectRoads` 가 그런 연결을 거부한다(`한 칸에서 양쪽으로 올라갈 수 없습니다`).
마주 보는 두 방향이라도 한쪽은 내려가야 한다 — 통과 비탈(0-1-2)은 그대로 된다.
도시 생성기에도 같은 판정을 넣었다(`cityGen.upBits`). 안 넣으면 생성기가 그릇 자리를
만들고, 그 연결만 조용히 거부되어 도로가 끊긴다.

### 바뀐 파일

| 파일 | 무엇을 |
|---|---|
| `src/world/slope.ts` | `surfaceAt` 재작성. `rampUpDir` 신규. `edgeHeight` 삭제 |
| `src/world/build.ts` | `canConnectRoads` 에 "두 방향으로 올라갈 수 없다" 규칙 |
| `src/world/cityGen.ts` | `upBits` 로 같은 규칙을 계획 단계에 적용 |
| `src/core/pick.ts` | 주석만(반 단계 → 한 단계) |

`TileSurface` 인터페이스가 그대로라 `chunkMesh` · `vehicleMesh` · `pedestrianLayer` ·
`signalLayer` 는 **한 줄도 안 고쳤다.** 절벽(`edgeWallAt`) 계산도 그대로다 — 꼭짓점마다
높이를 들고 다니는 구조라서 한 단계짜리 램프에도 그대로 맞는다.

## 2. 드래그 건설 → 두 점 + 확정 버튼

### 무엇이 틀렸나

지도를 손가락으로 훑으면 지나간 칸이 그대로 지어졌다. 태블릿에서 세 가지가 동시에
망가진다.

1. 도구를 든 채로는 **지도를 움직일 수 없다**(드래그가 곧 건설이라서).
2. 손이 미끄러지면 의도하지 않은 칸까지 지어지고 돈이 나간다. 되돌릴 방법이 없다.
3. 브레젠험 보간이라 대각선 드래그가 **계단 모양 도로**를 만든다. 도로는 면을 칠하는
   도구가 아니라 선을 긋는 도구인데도.

### 지금 흐름

```
첫 탭 = pos1        (선 도구면 네 방향 일직선이 바닥에 비친다)
둘째 탭 = pos2      (다시 누르면 끝점만 옮겨진다)
오른쪽 ✓ = 건설     ✕ = 취소 · Enter / Esc 도 같다
```

**확정을 누르기 전에는 돈이 한 푼도 나가지 않는다.** 그 사이 칸마다 색이 붙는다.

| 색 | 뜻 |
|---|---|
| 초록 | 지어진다 |
| 회색 | 이미 그렇게 되어 있다. 그냥 지나간다(과금 없음) |
| 빨강 | 못 짓는다. 그 자리만 비우고 나머지는 지어진다 |
| 노랑 테두리 | pos1 |
| 옅은 노랑 | 끝점을 찍을 수 있는 일직선(pos1 만 찍은 상태) |

확정 바에는 `도로 12칸 · 불가 2` 와 `₩1,200` 이 같이 나온다. 자금이 모자라면 ✓ 가
잠기지 않고 **"자금 부족"** 으로 표시된다(부분 건설은 되므로 막지 않는다).

### 선과 면

| 모양 | 도구 |
|---|---|
| 선(축으로 스냅) | 도로 · 활주로 · 유도로 · 상수도관 · 하수도관 · 배관 철거 · 전선 · 전선 철거 · 지하철 터널 |
| 면(직사각형) | 주거 · 상업 · 공업 지구 · 철거 |
| 한 채(탭 한 번) | 시설 전체 · 지하철역 · 지하철 철거 · 신호등 설치/제거 |

선 도구는 대각선으로 찍어도 **긴 쪽 축**을 따라 곧게 스냅된다. 상한은 선 120칸,
면 32×32 다.

### 원래 있던 것은 없어지지 않는다

예전에는 지구·시설 위로 도로를 그으면 그 자리가 조용히 헐렸고, 다른 지구 위에 지구를
덧칠하면 건물째 교체됐다. 학생이 제 도시를 지우는 사고의 원인이다. 지금은

- 도로가 지구·시설·활주로 위로 지나가면 **그 칸만 빨간색으로 건너뛴다**
- 이미 다른 지구인 칸은 교체되지 않는다(`이미 다른 지구입니다 · 철거 후 다시 지정하세요`)
- 바꾸고 싶으면 철거 도구를 먼저 쓴다

### 입력

모든 건설 도구가 `isPainting() === 'tap'` 이 됐다. **한 손가락 드래그는 언제나 지도
이동**이고, 두 손가락은 그대로 확대/이동이다. `core/input.ts` 는 안 고쳤다 — 이미
'tap' 모드를 지원하고 있었다.

건설 도구를 든 탭은 건물 정보 패널을 열지 않는다(`main.ts`). 두 점을 찍는 내내
패널이 떴다 닫혔다 하면 지도가 가려진다.

### 도로 연결

선을 따라 앞 칸과 이어 나가는 방식은 예전 드래그와 같다. 다만 **미리보기가 거짓말을
하지 않도록**, 비탈 검사를 "여기까지 지었다고 치면" 상태로 돌린다
(`build.ts: RoadProbe`). 선 전체를 이미 이어진 것으로 보면 아직 오지도 않은 칸 때문에
앞 칸이 막히므로, 앞에서부터 한 칸씩 확정해 나간다(`linkedUpto`).

이미 놓인 두 도로를 **잇기만 하는** 선택도 정당한 건설이다(돈이 안 나갈 뿐이다).
지을 칸이 0 이어도 확정이 되고, 그래야 T자 교차로를 만들 수 있다.

### 바뀐 파일

```
src/ui/placement.ts      신규 — 선/면 기하, 안내선, 상한
src/ui/placementBar.ts   신규 — 오른쪽 ✓ / ✕ 바
src/ui/tools.ts          재작성 — 두 점 상태기계 · 칸별 판정 · 계획 캐시
src/render/worldRenderer.ts  선택 범위 오버레이(setPlacement)
src/world/build.ts       RoadProbe
src/main.ts              입력 배선
index.html               #build-confirm
src/ui/gameChrome.css    #build-confirm 스타일
src/ui/constructionMenu.ts  문구
```

계획은 한 프레임에 세 번 읽히므로(오버레이 · 확정 바 · 버튼 상태) 입력 서명이 같으면
지난 계산을 돌려준다. 1,024칸짜리 범위를 매 프레임 세 번 계산하면 그것만으로 프레임이
흔들린다.

## 3. 검증

`tools/check/placementCheck.ts` 에 5개를 더했다(총 17개).

- 램프는 낮은 칸 하나가 통째로 지고 **높은 칸·지형은 평평하다**
- 한 칸에서 양쪽으로 올라가는 도로는 거부된다
- **램프 옆으로 지면이 뚫리지 않는다** — 램프 주변 모든 +tx/+ty 이음매에서
  자기 지면이 이웃보다 높으면 반드시 벽이 서는지 전수 확인
- 선 도구는 일직선으로 스냅되고 원래 있던 것을 덮지 않는다
- 확정을 눌러야 지어지고, 취소하면 아무 일도 없다

`metroCheck` 와 `placementVisual` 의 드래그 호출을 두 점 호출로 고쳤다.

```
npm run build            통과 (tsc --noEmit + vite build)
npm run check            아래 3건을 빼고 전부 통과
```

**이 작업 전부터 깨져 있던 3건**(upstream main 에서 같은 값으로 재현했다. 이번 변경과
무관하다):

| 검사 | 증상 |
|---|---|
| `service` 23 | 필수 시설을 놓아도 입주율 24.09% → 24.08% |
| `sim` | 최종 입주율 24% 가 목표 범위 밖 |
| `special` | 시설 종류 수 27 vs 기대 26 |

`sim` 은 이번 변경 전후로 **숫자가 한 자리도 다르지 않다**(인구 1206 · 자금 90,051 ·
재건축 철거 42채). 시뮬레이션 쪽은 건드리지 않았다는 증거다.

## 4. 남은 것 / 결정이 필요한 것

- **철거를 면으로 뒀다.** 범위 철거는 실수하면 피해가 크지만, ✓ 를 누르기 전에는
  아무 일도 없고 빨강/초록이 다 보이므로 지금은 면이 맞다고 봤다. 한 칸씩으로
  되돌리려면 `placement.ts` 의 `AREA_TOOLS` 에서 `bulldoze` 만 빼면 된다.
- **신호등·지하철역은 탭 한 번**으로 남겼다. 한 대상짜리 도구라서다. 도로 구간을
  잡아 신호등을 한 번에 깔고 싶으면 선으로 바꿀 수 있다.
- 두 단계 이상 차이 나는 고도는 예전처럼 절벽이다(램프는 한 단계만 잇는다).
- 경사 타일 위의 건물·시설은 여전히 평평한 땅에만 선다(설계 그대로).
