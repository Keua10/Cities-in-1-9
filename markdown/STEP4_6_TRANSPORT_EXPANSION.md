# STEP 4.6 교통 시설 확장 — 공항·항구

## 목적

기존 STEP 4.6의 단순 3×3 공항/항구를 TheoTown 계열의 도시 운영 시설에 가깝게 확장한다. 기존 `Build.Civic`/`FAC_BASE` 시설 저장 구조와 기존 시설 ID 0~20은 그대로 유지하며, 새 시설 ID는 뒤에만 추가한다.

## 항구

### 등급 및 운용량

| 종류 | 부지 | 도시 레벨 | 최대 선박 | 운용 방식 |
|---|---:|---:|---:|---|
| 소형 여객항 | 3×3 | 3 | 2척 | 여객 전용 |
| 소형 화물항 | 3×3 | 3 | 2척 | 화물 전용 |
| 중형 복합항 | 5×5 | 4 | 5척 | 여객+화물 하이브리드 |
| 대형 복합항 | 7×7 | 5 | 13척 | 여객+화물 하이브리드 |

5×5부터는 반드시 하이브리드이며 건물을 누르면 `교통 시설 운영` 패널이 열린다. 여객선/화물선 슬라이더의 합은 최대 운용 가능 선박 수를 넘을 수 없다. 한쪽을 늘려 한도를 넘으면 반대쪽 배정이 먼저 자동 감소한다.

기본 배정은 중형 3+2척, 대형 7+6척이다. 설정은 `macro.transport.harbors["tx,ty"]`에 희소하게 저장한다. 기존 저장본에는 필드가 없어도 정상 동작한다.

### 기능

- 여객선 1척: 외부 방문객 60명/일 처리.
- 도시 내부 수상교통: 가동 중이며 여객선이 배정된 항구가 2곳 이상일 때 활성화. 여객선 1척당 240회/일의 수상교통 처리량을 제공한다.
- 화물선 1척: 산업 화물 수출 수요 160을 추가한다.
- 운항 수익: 여객선 80/일, 화물선 140/일.
- 모든 항구는 도로 연결, 수역 인접, 전력 50% 이상을 만족해야 실제 운항한다.

## 공항

| 등급 | 부지 | 도시 레벨 | 최대 항공기 | 최소 직선 활주로 |
|---|---:|---:|---:|---:|
| 소형 공항 | 3×3 | 3 | 2대 | 6칸 |
| 중형 공항 | 5×5 | 4 | 6대 | 10칸 |
| 대형 공항 | 7×7 | 5 | 14대 | 14칸 |

공항 터미널만 설치해서는 운항하지 않는다. 시설 메뉴의 `공항 부품`에서 **활주로**와 **유도로**를 별도로 그려야 한다.

가동 조건은 다음과 같다.

1. 공항 터미널에 도로 연결.
2. 전력 공급 50% 이상.
3. 터미널 footprint 가장자리에 유도로가 직접 연결.
4. 해당 유도로망이 활주로까지 연결.
5. 연결된 활주로 중 직선 연속 길이가 공항 등급의 최소 길이 이상.

활주로/유도로는 기존 `build` 저장 바이트에 `Build.Runway=5`, `Build.Taxiway=6`을 append-only로 추가한다. 도로망이나 STEP 3.2 차량 통행 규칙에는 편입하지 않는다. 렌더링도 기존 지면 메시의 UV만 사용하므로 청크당 draw-call 구조를 늘리지 않는다.

공항은 이번 단계에서 도시 간 목적지 직접 연결 대신 방문객 유입 역할을 쓴다. 가동 항공기 1대당 방문객 180명/일, 운항 수익 180/일을 제공한다.

## 도시 시뮬레이션 효과

교통 시설은 기존 서비스 커버리지(`ServiceField`)에 억지로 넣지 않고 별도 파생 계산 `TransportSystem`에서 처리한다. 시설 배치 자체는 기존 저장 구조다.

- 공항/여객항 방문객 → 상업 수요 보조.
- 도시 내 수상교통 처리량 → 주거/상업 수요 소폭 보조.
- 화물항 → 공업 수요 보조.
- 운항 수익 → 하루 경계에서 도시 자금에 1회 반영.
- 방문객/화물/수상교통 → 번영도에 소폭 기여.
- 수요 보조는 `Math.max` 기반 floor라 프레임마다 누적 폭주하지 않는다.

## 저장 호환성

기존 시설 ID 0~20은 변경하지 않았다.

- 17 통신탑 유지
- 18 기존 공항 → 소형 공항으로 확장
- 19 기존 항구 → 소형 여객항으로 확장
- 20 교도소 유지
- 21 소형 화물항
- 22 중형 복합항
- 23 대형 복합항
- 24 중형 공항
- 25 대형 공항

시설 앵커 코드는 기존 `FAC_BASE=9` 뒤에 그대로 이어지며 `BLD_COVERED=254`, `BLD_NONE=255`와 충돌하지 않는다. `WORLD_SEED`, 타일 크기, 지형 노이즈, RLE 코덱, 기존 도로 연결 규칙은 변경하지 않았다.

## 기존 입력 패치 보존

시설은 모바일/PC 모두 클릭·탭으로 설치하고 드래그하면 카메라 이동으로 전환되는 기존 입력 패치를 그대로 사용한다. 활주로/유도로는 연속 건설 도구이므로 드래그가 건설 입력으로 동작한다.

## 이번 단계에서 의도적으로 넣지 않은 것

- 도시 간 특정 상대 도시를 직접 선택해 노선을 만드는 기능: 현재 프로젝트에 도시 간 교통 노선 API/저장 규격/UX가 정의되어 있지 않아 임의 포맷을 만들지 않았다. 현재 공항은 방문객 유입, 항구는 내부 수상교통/화물 역할을 담당한다.
- 개별 비행기/배의 화면상 애니메이션: 운용량과 도시 효과는 구현했지만 STEP 3.2 차량 규칙을 침범하지 않도록 별도 이동체 시뮬레이션은 추가하지 않았다.

## 검사

`tools/check/run.mjs`에 `transport` 검사를 추가했다.

- 기존 0~20 시설 ID 보존
- 신규 21~25 append-only ID
- 공항/항구 3×3·5×5·7×7 크기와 해금 레벨
- 항구 2/5/13척, 공항 2/6/14대
- 3×3 여객/화물 분리, 5×5 이상 하이브리드
- 하이브리드 배분 합계 상한
- 유도로→활주로 연결 및 최소 직선 길이
- 5×5/7×7 시설 아틀라스 확장
