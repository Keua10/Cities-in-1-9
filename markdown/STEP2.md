# 2단계 — 도로 + 지구 지정

이 문서는 **1단계 `README.md` 를 대체하지 않는다.** Firebase·Vercel 세팅 설명은 그대로
`README.md` 에 남아 있다. 이 문서는 2단계에서 무엇이 어떻게 바뀌었는지만 적는다.

---

## 0. ChatGPT 에게 — 먼저 읽을 것

이 zip 안의 파일은 **이미 `npm run build`(타입 검사 + vite 빌드)를 통과한 상태**다.
논리 검증도 끝냈다(11번 참고).

**해야 할 일은 파일을 그대로 덮어쓰는 것뿐이다.**

- 코드를 "개선" 하거나 변수 이름을 바꾸지 말 것. 통과한 빌드가 깨진다.
- 새 의존성이 없다. `package.json` 도 안 바뀌었다. `npm install` 다시 할 필요 없다.
- 아래 5번의 "건드리면 안 되는 파일" 은 이 zip 에 들어 있지도 않다. 그대로 두면 된다.
- 덮어쓴 뒤 `npm run build` 를 한 번 돌려 통과하는지만 확인한다.

`index.html` 에서 **`btn-paint`(지형 칠하기) 버튼이 사라졌다.** 1단계에서 저장 경로를
확인하려고 넣은 임시 기능이었고, `main.ts` 의 관련 코드도 함께 제거됐다.
어딘가에 `btn-paint` 를 참조하는 코드가 남아 있으면 그건 덮어쓰기가 덜 된 것이다.

## 1. 이 단계에서 만든 것

- 지형과 별개인 **build 레이어**. 칸마다 "무엇을 지었는가" 를 1바이트로 들고 있다.
- **도로.** 4방향 연결, 16가지 모양이 이웃에 따라 자동으로 바뀐다. 청크 경계를 넘어서도 이어진다.
- **주거·상업·공업 지구.** 도로에 접했는지에 따라 색이 달라진다.
- **철거.** build 레이어만 지우고 지형은 그대로 둔다.
- **칠하기 제스처.** 도구가 켜져 있을 때 한 손가락 드래그 = 그리기, 두 손가락 = 지도 이동.
- Firestore 저장/복원 연결.

**돈은 계산하지 않는다.** 건설비·인구·수요는 3단계에서 매크로가 들어올 때 붙인다.
지금 도로는 무료다.

## 2. 설계에서 중요한 결정 세 가지

### 2-1. 도로를 `Terrain` 에 추가하지 않았다

1단계 `README.md` 는 "지형 ID 를 `Terrain` 끝에 추가하면 된다" 고 안내했다.
타일 칠하기 수준에서는 맞지만 도로·지구에는 쓸 수 없다.

1. 도로는 연결 모양이 16가지다. 지형 ID 로 넣으면 이웃이 바뀔 때마다 저장 데이터를
   다시 써야 한다. 연결 모양은 이웃에서 매번 계산할 수 있으므로 저장할 값이 아니다.
2. 지구를 철거하면 원래 지형으로 돌아가야 한다. 칸당 값이 하나뿐이면 "풀밭 위의
   주거지구" 를 표현할 수 없고, 철거했을 때 무엇으로 되돌릴지 알 수 없다.
3. 3단계의 건물·차량이 같은 칸에 얹힌다. 지형과 시설을 한 배열에 섞으면 반드시 되돌려야 한다.

그래서 칸당 바이트를 하나 더 쓴다. **아무것도 짓지 않은 청크는 배열 자체를 만들지 않으므로
(null) 실제 메모리는 학생이 건드린 청크에만 늘어난다.**

### 2-2. 정점을 하나도 추가하지 않았다

지구를 반투명으로 얹으려면 타일마다 사각형이 하나씩 더 필요하다.
청크당 사각형이 **5,600 → 9,700 개**로 늘고 정점 버퍼가 두 배(360KB → 620KB)가 된다.
메시 28개를 물고 있으면 17MB다. 아이패드에서 치를 이유가 없는 값이다.

대신 **타일 윗면의 UV 만 다른 셀로 바꾼다.**

- 도로 칸 → 윗면 셀 = `ROAD_CELL_BASE + 연결마스크`
- 지구 칸 → 윗면 셀 = `ZONE_CELL_BASE + 종류*2 + (도로접함 ? 1 : 0)`
- 그 외 → 윗면 셀 = 지형 ID (기존과 동일)

정점 수도 드로우콜도 그대로다. 청크 1개 = 메시 1개 = 드로우콜 1회 구조가 유지된다.
고도 음영 사각형은 이미 윗면 위에 겹쳐 그려지므로 **도로·지구 위에도 높이에 따른 밝기가
그대로 얹힌다.** 따로 처리한 게 아니라 공짜로 따라온 것이다.

지구가 불투명 색이 되는 건 의도한 것이다(고전 심시티 방식). 3단계에서 건물이 들어서면
그 위를 건물 스프라이트가 덮는다.

### 2-3. 도로·지구 그림은 코드가 그린다

`public/sprites/terrain.png` 가 아직 보류 상태다. 그림을 기다리다 2단계가 멈추면 안 되므로,
고도 음영과 똑같이 **`atlas.ts` 가 도로 16칸과 지구 6칸을 코드로 그려서** 아틀라스 뒤에 붙인다.

**이번 단계의 그림 작업은 0이다.**

셀 번호는 저장되지 않는다. 나중에 진짜 그림으로 교체하거나 셀 순서를 바꿔도 이미 저장된
도시는 안 깨진다.

## 3. 데이터 구조

### 3-1. build ID (`src/world/build.ts`)

```ts
export const Build = {
  None:  255,   // 아무것도 안 지음
  Road:  0,
  ZoneR: 1,     // 주거
  ZoneC: 2,     // 상업
  ZoneI: 3,     // 공업
} as const;
```

**`Build.None` 이 255 인 것이 이 설계의 핵심 장치다.** `constants.ts` 의 `OVERRIDE_NONE`
과 같은 값이라, `codec.ts` 의 압축 형식을 **한 글자도 바꾸지 않고** 그대로 재사용한다.
`encodeOverride` 는 배열이 전부 255 면 `null` 을 돌려주므로, 아무것도 안 지은 청크는
Firestore 필드가 아예 생기지 않는다.

두 값이 갈라지면 `build.ts` 의 `BUILD_NONE` 선언에서 **컴파일 오류가 난다.** 일부러 그렇게 뒀다.

새 ID(건물·군사시설)는 **반드시 4번부터 뒤에 붙인다.** 중간에 끼우면 저장된 도시가 어긋난다.

### 3-2. 저장

`cities/{uid}/chunks/{cx}_{cy}` 문서에 필드 하나가 늘었다.

```
tiles     지형 오버레이   (기존)
heights   고도 오버레이   (기존, 지금도 항상 null)
build     도로·지구       ★ 2단계에서 추가. 형식은 tiles 와 완전히 동일
updatedAt
```

- **`SCHEMA_VERSION` 은 1 그대로다.** 순수 가산이라 마이그레이션이 필요 없다.
  1단계에 저장된 문서에는 `build` 가 없고, `decodeOverride(null)` 이 `null` 을 돌려주므로
  "아무것도 안 지음" 으로 자연스럽게 읽힌다.
- **`firestore.rules` 는 고치지 않았다.** 청크 규칙은 필드를 검사하지 않는다.
  Firebase 콘솔에서 할 일이 없다.
- 실측: 도로 5칸 = **20자**. 청크를 격자 도로로 채워도 몇 KB다. 문서 한도 1MB 의 1% 미만.

## 4. 규칙

### 4-1. 도로

```
못 놓는 경우
  1. 아직 개척하지 않은 청크
  2. 물 (다리는 이후 단계)
  3. 한 칸이 여러 방향으로 비탈지는 경우 (아래)
```

지구 위에 도로를 놓으면 지구를 덮어쓴다. 이건 허용이다.

### 4-2. 경사 판정 — 설계 문서에서 한 번 수정된 부분

지형 생성이 **이웃 타일 간 고도차를 항상 0 또는 1 로 보장**한다(1단계 README 6장, 60만 지점
검증됨). 그래서 "너무 가팔라서 못 놓는" 경우는 **아예 없다.**

막아야 하는 건 한 칸이 여러 방향으로 동시에 비탈지는 경우다. 그런 칸은 어떤 모양으로도
그릴 수 없다.

```
경사 연결 = 맞닿은 두 도로 타일의 고도가 다른 연결

0개   자유
1개   허용. 비탈의 시작/끝이고 이 칸 자체는 평평하다.
2개   서로 반대 방향일 때만 허용 (곧은 비탈길)
3개+  거부
```

> 처음 설계 문서에는 "비탈에는 코너·T·십자를 만들 수 없다" 고 적었는데, 이건 과한 표현이라
> 구현하면서 바로잡았다. **비탈 아래에 T자 교차로를 만드는 건 문제가 없다.** 그 칸 자체는
> 평평하기 때문이다. 실제로 막히는 건 "올라가면서 동시에 옆으로도 올라가는" 코너다.

검사는 **놓을 칸뿐 아니라 이웃 4칸까지** 한다. 내 칸만 보면 이웃이 규칙을 깨는 모양으로
바뀌는 걸 놓친다.

### 4-3. 지구

```
못 지정하는 경우
  1. 아직 개척하지 않은 청크
  2. 물
  3. 도로 위 (먼저 철거해야 함)
```

**도로 인접은 배치 조건이 아니라 표시 조건이다.** 도로 없이도 지정은 되고 색만 어둡게
나온다. 3단계에서 "도로에 접한 지구만 개발" 로 이어질 자리라, 학생이 지금부터 그 차이를
눈으로 알 수 있어야 한다.

## 6. 성능을 위해 일부러 이렇게 한 것

나중에 누가 "왜 이렇게 짰지" 하고 고치면 프레임이 떨어진다. 세 가지를 적어둔다.

### 6-1. `World.setBuild` 는 `revision` 을 올리지 않는다

올리면 `ChunkMesh.syncIfStale` 이 매 프레임 `writeAllUVs` 를 돌린다. 그건 4096칸을 훑고
128KB 정점 버퍼를 통째로 GPU 에 올리는 일이다. 드래그로 도로를 그으면 그게 초당 60번
돌아간다.

대신 도구가 `WorldRenderer.invalidateTile` 로 **바뀐 칸과 이웃 4칸만** 직접 고친다.
UV 8개씩 5칸 = 40개 float 쓰기로 끝난다.

`writeAllUVs` 는 청크가 처음 구워질 때와 불러오기 직후에만 돈다.

### 6-2. `sampleBuild` 는 청크를 만들지 않는다

연결 마스크를 계산하려면 옆 청크를 봐야 하는데, `getChunk` 를 쓰면 화면 밖 청크까지
`generateChunk`(4096칸 노이즈)가 돌아버린다. `sampleBuild` 는 메모리에 있는 청크와
`pending`(불러왔지만 아직 안 펼친 저장 데이터)까지만 보고, 없으면 `Build.None` 을 돌려준다.

### 6-3. `resolveTop` 의 빠른 길

`chunk.build` 가 `null` 이거나 그 칸이 `Build.None` 이면 배열 읽기 한 번으로 지형 ID 를
돌려준다. 대부분의 칸이 여기로 빠지므로, 도로가 없는 청크는 1단계와 성능이 같다.

## 7. 조작법

| | 선택 도구 | 칠하기 도구 (도로·지구·철거) |
|---|---|---|
| 한 손가락 드래그 | 지도 이동 | **그리기** (지도가 안 움직임) |
| 두 손가락 | 이동 + 확대/축소 | 이동 + 확대/축소 (그대로) |
| 탭 | 타일 선택 | 그 칸에 배치 |
| 마우스 드래그 | 지도 이동 | 그리기 |

두 손가락으로 늘어나면 진행 중이던 그리기를 **즉시 끊는다.** 핀치하면서 도로가 그어지면
학생이 지도를 못 움직인다.

빠르게 그으면 포인터 이벤트가 타일을 건너뛰므로, 직전 칸과 현재 칸 사이를 타일 좌표
기준으로 메운다(한 번에 최대 64칸). 손가락이 화면 밖으로 나갔다 들어오면 이어 긋지 않는다.

배치가 거부되면 HUD 아래에 사유가 2.5초간 뜬다. 팝업이나 소리는 없다.

## 8. 넣는 순서

1. zip 을 풀어 저장소에 **경로 그대로** 덮어쓴다.
2. `npm run build` 통과 확인.
3. **`main` 이 아니라 브랜치에 올린다.** 학생들이 보는 주소를 건드리지 않기 위해서다.
   ```bash
   git switch -c step2-roads
   git add .
   git commit -m "2단계: 도로와 지구 지정"
   git push -u origin step2-roads
   ```
4. Vercel 이 만들어 준 **미리보기 URL** 에서 9번 체크리스트를 돈다.
5. 다 통과하면 `main` 에 합친다.

아이패드에서 작업한다면 `github.com` 을 `github.dev` 로 바꿔 웹 에디터에서 파일을
붙여넣고 커밋하면 된다. 다만 파일이 13개라 컴퓨터에서 하는 편이 빠르다.

**Firebase 콘솔 작업 없음. Vercel 환경변수 변경 없음.**

## 9. 완료 판정 체크리스트

### 도로

- [ ] 도로 도구로 탭 → 그 칸이 도로가 된다
- [ ] 도로 옆에 도로를 놓으면 **양쪽 모양이 같이 바뀐다** (막다른길 → 직선 → T자 → 십자)
- [ ] 연결되지 않은 방향에는 연석(밝은 선)이 보인다
- [ ] 청크 경계를 넘어 도로를 이어도 연결 모양이 정상이다 (격자 보기로 경계 확인)
- [ ] 물 위에는 안 놓인다
- [ ] 곧은 비탈길은 놓인다
- [ ] 비탈에서 꺾으려 하면 거부되고 HUD 에 사유가 뜬다
- [ ] 안개를 끄고 미개척 청크에 놓으려 하면 거부된다

### 지구

- [ ] 주거·상업·공업이 각각 초록·파랑·노랑으로 칠해진다
- [ ] 도로에 접한 지구가 안 접한 지구보다 밝다
- [ ] 지구 옆에 도로를 놓으면 **그 지구 색이 즉시 밝아진다**
- [ ] 도로를 철거하면 옆 지구 색이 다시 어두워진다
- [ ] 도로 위에 지구를 지정하려 하면 "도로를 먼저 철거해야 합니다" 가 뜬다

### 철거

- [ ] 도로·지구가 지워지고 **원래 지형이 그대로 돌아온다**
- [ ] 고도와 절벽이 그대로다
- [ ] 절벽 옆면이 아스팔트로 바뀌지 않는다 (경사면에 도로를 깔고 확인)

### 저장

- [ ] 도로를 깔고 5초 뒤 "저장됨" 이 뜬다
- [ ] 새로고침하면 도로와 지구가 그대로 복원된다
- [ ] 복원된 도로의 연결 모양도 정상이다
- [ ] Firestore `cities/{uid}/chunks/{cx}_{cy}` 문서에 `build` 필드가 생긴다
- [ ] 전부 철거하고 저장하면 `build` 가 `null` 이 되거나 문서가 사라진다
- [ ] **1단계에서 만든 기존 도시로 로그인해도 오류 없이 뜬다**
- [ ] 두 기기 충돌 처리가 여전히 동작한다

### 터치 (아이패드 실기기 — 컴퓨터로는 확인 불가)

- [ ] 선택 도구에서 한 손가락 드래그 = 지도 이동 (1단계와 동일)
- [ ] 도로 도구에서 한 손가락 드래그 = 도로가 **끊김 없이** 이어진다
- [ ] 도로 도구에서 **두 손가락 = 지도 이동/확대**가 되고 그동안 도로가 안 그려진다
- [ ] 그리다가 손가락을 하나 더 얹으면 그리기가 멈춘다
- [ ] 빠르게 그어도 타일이 건너뛰지 않는다
- [ ] 도구 버튼이 한 손으로 닿는다 (저장/로그아웃 줄 위에 있다)

### 성능 (최우선)

- [ ] 도로를 길게 드래그하는 동안 fps 가 1단계와 같다
- [ ] 청크 하나를 도로로 가득 채워도 fps 가 유지된다
- [ ] HUD 의 `메시` 수가 28 이하로 유지된다
- [ ] 최대 축소에서 도로가 깔린 영역을 지나가도 프레임이 안 떨어진다

## 10. 문제가 생기면

- **도로가 안 보인다** → 아틀라스 셀이 안 그려진 것. HUD 에 "그림: 임시 타일 사용 중" 이
  떠 있어도 도로는 나와야 한다(도로는 코드가 그린다).
- **도로 모양이 안 바뀐다** → `WorldRenderer.invalidateTile` 이 안 불린 것. `tools.ts` 의
  `refresh` 확인.
- **청크 경계에서만 도로가 끊겨 보인다** → `World.sampleBuild` 의 `pending` 조회가 빠진 것.
- **저장은 되는데 복원이 안 된다** → `applyOverride` 에서 `chunk.build = ov.build` 확인.
- **드래그하면 지도가 같이 움직인다** → `input.ts` 의 `isPainting` 분기가 안 들어간 것.
- 되돌리려면 `main` 브랜치가 그대로 살아 있다. `step2-roads` 를 지우면 끝이다.

## 12. 3단계로 넘어갈 때

이 구조는 3단계를 염두에 두고 짰다.

- **도로 그래프는 저장하지 않는다.** 접속할 때 개척된 청크의 build 배열을 훑어 노드/간선을
  만들면 된다. 매크로/미시 분리 원칙과 맞는다.
- **연결 마스크를 저장하지 않았으므로** 나중에 도로 등급(2차선·고속도로)이나 다리를 넣어도
  기존 도시가 안 깨진다.
- **지구는 "수요를 만드는 칸" 의 목록**이다. 매크로는 청크별 지구 개수만 세면 된다.
- 건물 개별 상태가 필요해지면 build 레이어 뒤에 배열을 하나 더 붙인다. 같은 패턴이고,
  `ChunkDoc` 에 필드 하나 추가로 끝난다.
- `Build` ID 에 여유가 많다(4~254). 건물·군사시설은 여기에 이어 붙인다.
