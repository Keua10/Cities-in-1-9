# 대도시 생성기 재작성

기준: main `edac240`. 범위는 "맵 초기화"와 첫 접속이 부르는 초기 도시 생성
(`src/world/cityGen.ts`, `src/world/citySeed.ts`, `src/world/cityUtilities.ts`)이다.
저장 형식, `SCHEMA_VERSION`, 시설 ID, `WORLD_SEED`, 지형 함수, 청크 메시 구조는
건드리지 않았다.

## 1. 예전 생성기가 무엇을 틀렸는가

전부 코드를 읽어서 짐작한 것이 아니라 생성 결과를 계측해서 확인했다.
아래 수치는 도시 0~5를 실제로 생성하고, 그중 세 도시를 매크로 시뮬레이션으로
게임 시간 10일 돌려서 잰 값이다.

| 문제 | 계측값 |
| --- | --- |
| 도로망이 갈라짐 | 도로 연결 비트로 걸어 보면 **최대 5조각**. 도시 2는 도로의 33%가 도심에서 도달 불가 |
| 용도 비율 붕괴 | 도시 0 의 R/C/I 타일 = **3452 / 395 / 37**. 일자리/필요 = **0.21** (실업률 79%) |
| 반대쪽 극단 | 도시 4 는 일자리/필요 = **2.45** |
| 입주율 | **0.47 ~ 0.61** |
| 재정 | 도시 0 수입 18,445 / 지출 23,233 — **첫날부터 적자** |
| 죽은 지구 | 지구 타일의 **34%** 가 도로에 닿지 않아 영원히 빈 땅 |
| 서비스 커버율 | 경찰 0.40 / 병원 0.33 / 학교 0.49 까지 내려감 |
| 시설 수 | **182채** (도시 크기와 무관한 고정 격자) |
| 난수 | 좌표 해시만 사용 → **"맵 초기화"를 눌러도 매번 같은 도시** |

원인은 네 가지였다.

### 1.1 영역과 반경이 어긋났다

기본 도시는 2×2 청크 = 128타일인데 `CITY_RADIUS`는 70이었다. 지름 140 > 128
이라 구역 씨앗의 절반이 영역 밖으로 나가 `pushSeed`에서 버려지고, 남은 쪽으로
도시가 쏠렸다. 도심이 (91,103) 같은 구석에 서는 도시가 그래서 나왔다.
소스 주석도 `4x4 청크 = 256`으로 남아 있었다.

### 1.2 도로 연결을 나중에 추측했다

`cityGen`이 "맞닿음" 기준으로 도로를 깔고, `citySeed`가 `world.setBuild`를
몽키패치한 뒤 주변 도로의 진행축을 재서 연결 비트를 만들었다. 그런데 도심 연결
검사(`pruneDisconnected`)는 **그 전에, 맞닿음 그래프로** 돌았다. 두 그래프가
다르니 실제로는 도심과 끊긴 도로 덩어리가 그대로 남았다.

게다가 A\* 길찾기가 고도차 2 이상인 칸을 그냥 밟았다. `build.ts`의
`canConnectRoads`는 그런 연결을 거부하므로, 절벽을 가로지르던 길이 나중에
끊기고 그 뒤쪽이 통째로 섬이 됐다.

### 1.3 용도 비율이 지형 운에 맡겨졌다

구역 종류를 각도로 배정하고 지형이 자르는 대로 뒀다. 공업 씨앗이 물이나
산에 걸리면 도시 전체에 일자리가 없어진다.

### 1.4 시설을 정원이 아니라 고정 격자로 깔았다

소공원 11칸마다, 공원 16칸마다… 하는 식이라 도시 크기와 무관하게 182채가
섰다. 유지비가 수입을 넘겼다.

추가로 `cityUtilities`는 부지를 못 찾으면 **예외를 던졌다.** 이 함수는 첫 접속
경로(`main.ts`)에서 불리므로 지형이 조금만 험하면 게임이 시작조차 못 한다.
배관·전선도 도시 발자국이 아니라 128×128 전면에 깔았다.

## 2. 다시 만든 원칙

### 2.1 경계는 계산이 아니라 규칙이다 (요구 1)

모든 쓰기가 `inside()`를 통과한 좌표에만 일어난다(`EDGE = 4`). 구역 고리
반지름도 영역 크기에서 잡는다 — 도심은 영역 가운데 30% 안에서만 고르고,
바깥 고리는 `SPAN × 0.27~0.32`, 구역 반경은 최대 17이다. 검사가 기본 2×2
청크 밖의 모든 쓰기를 0으로 강제한다.

### 2.2 도로망은 추측하지 않고 만든다 (요구 2, 5)

`growRoadNetwork`가 **연결 그래프를 직접 키운다.**

1. 간선도로(A\*)와 구역별 이면도로 격자를 "후보"로 모은다. A\*는 **고도차 1을
   넘는 칸을 아예 밟지 않는다.**
2. 도심을 뿌리로 후보를 하나씩 붙여 나간다. 간선(두 칸 사이 연결)을 붙일
   때마다 `build.ts`와 같은 두 규칙을 그 자리에서 검사한다 — 고도차 ≤ 1,
   그리고 한 칸이 여러 방향으로 비탈지지 않을 것(마주 보는 두 방향은 허용).
3. 이 그래프에 끝내 못 들어온 후보는 **놓지 않는다.**
4. 실제로 놓을 때는 `placeGeneratedRoad`로 고립(연결 비트 0) 상태로 깔고,
   계획한 간선만 `canConnectRoads`를 통과시켜 연다. 마지막 관문이 계획이 아니라
   `build.ts` 한 곳이므로 학생이 직접 그린 도로와 규칙이 완전히 같다.
5. 마지막 안전망으로 실제 `roadsConnected`를 다시 걸어 도심에서 못 가는 도로를
   철거한다. 위 단계가 맞다면 지울 것이 없어야 하고, 실제로 없다.

그래서 완성된 도로망은 정의상 **한 덩어리이고, 모든 연결이 규칙을 만족하며,
고립된 조각이 없다.** 간선을 2칸 폭으로 넓히던 것은 없앴다 — 이 게임의 도로는
한 칸이 이미 양방향이고 나란한 두 줄은 서로 연결되지 않으므로, 2칸 폭은
통행량을 늘리지 못하면서 유지비와 혼란만 늘린다.

`citySeed.ts`의 몽키패치와 흐름 추정은 통째로 삭제했다. 이 파일은 기존 import
경로를 유지하는 재노출 창구로만 남는다.

### 2.3 용도 비율은 목표에서 거꾸로 잡는다 (요구 2, 6)

`sim/config/macro.ts`의 균형식에서 역산한다.

```
일자리 정원 = 주거 정원 / RESIDENTS_PER_JOB(1.35)
상업 정원   = 인구 × SHOP_JOBS_PER_RESIDENT(0.18)
→ 정원비 R : C : I = 1 : 0.18 : 0.56
→ 타일당 평균 정원(주거 11 · 상업 8.5 · 공업 13)으로 나누면
  타일비 ≈ 58% : 14% : 28%
```

칠하는 순서도 뒤집었다. 칸마다 잡음을 굴리는 대신,

1. 칠할 수 있는 칸 N을 센다
2. 공업 0.21N, 상업 0.145N을 할당량으로 정한다
3. 공업 씨앗에서 **할당량이 찰 때까지만** BFS로 키운다 → 공업은 항상 도시
   한쪽에 뭉치고, 지형이 어떻게 생겼든 총량이 맞는다
4. 공업 둘레 세 칸을 상업 완충대로 바꾼다 → 주거와 공업 사이에 **항상**
   상업 띠가 생긴다(`INDUSTRY_NUISANCE_RADIUS`가 6이므로 이 띠가 공업 혐오를
   받아낸다)
5. 도심·부도심에서 남은 상업 할당량을 키우고, 나머지는 전부 주거

공업 할당량을 0.28이 아니라 0.21로 낮춘 것은 계측 결과다. 0.28이면 공업
정원이 주거의 0.70배가 되어(목표 0.56) 일자리가 남고, 공업 혐오만 커졌다.

### 2.4 건물은 큰 것부터 놓는다

예전에는 한 번만 훑으면서 칸마다 등급을 정했다. 먼저 놓인 1×1 집 한 채가 그
자리에 설 수 있었던 3×3 아파트를 영원히 막는다. 실제로 주거 건물 등급 분포가
**L1 1154 / L2 106 / L3 1**로 무너져 있었다. 이제 3×3 → 2×2 → 1×1 순서로 세 번
훑고, 앞 단계에서 자리를 못 잡은 칸은 다음 단계에서 한 등급 낮춰 다시 시도한다.

### 2.5 시설 수는 정원과 도달 범위 둘 다에서 나온다

```
소방서  건물 220채당 1      경찰서  3,000명당 1
병원    5,000명당 1         학교    2,500명당 1
```

여기에 **면적 조건**을 함께 건다. 서비스는 도로 BFS로 퍼지므로(반경 30~55),
정원이 남아돌아도 반경 밖 동네는 "시설이 없는 동네"다. 정원만 보고 깔았더니
경찰 커버율이 0.69까지 떨어졌다. 둘 중 큰 쪽을 쓴다.

복지(공원·체육시설·소공원)는 **면적 적분**으로 잡는다. 시설 하나가 뿌리는
복지 총량은 `strength × π × r² / 3`(선형 감쇠의 원뿔 부피)이므로, 도시 넓이로
나누면 평균 복지 점수가 나온다. 목표는 1.3 — 저소득(0.35)·중산층(0.9) 요구를
완전히 채우고 고소득(1.8)도 7할을 채우는 선이다. 1.8까지 채우려면 공원이 배로
필요한데 그 유지비가 만족도 이득보다 크다.

필수 서비스는 **지구를 가리지 않고** 뿌린다. 주거지 쪽으로 당겼더니 공업지구에
소방서도 경찰서도 없는 도시가 나왔고(`SERVICE_WEIGHT`의 공업 소방 가중치가
0.16으로 가장 크다), 3단계 공장 입주율이 0.22까지 내려갔다. 학교만 예외로
주거지 쪽에 둔다 — 공업지구의 학교 가중치는 0이다.

### 2.6 기반시설 (요구 3)

`cityUtilities`를 다시 썼다.

- **절대 예외를 던지지 않는다.** 자리를 못 찾으면 덜 놓는다.
- 배치는 **도로가 실제로 깔린 범위** 안에서만 한다.
- 소각장·화장장·묘지도 정원과 반경 둘 다로 잡는다. 이게 가장 큰 발견이었다 —
  `macro.evaluate`는 주거 건물마다 `0.15 × (1 − 소각 품질) + 0.10 × (1 − 화장
  품질)`을 깎는다. 합쳐서 0.25로, 서비스 감점 상한(0.45)에 버금가고 통근이나
  공업 혐오보다 크다. 예전 개수로는 주거 건물 평균 감점이 **0.163**이었다.
  입주율이 0.6에서 안 올라가던 진짜 이유가 이것이었고, 고치니 0.028이 됐다.
- 시설을 **고르게** 뿌린다. 소각장은 정원이 1만이라 서너 채면 충분해 보이지만
  반경 64짜리 도로 BFS라서 한쪽에 몰리면 반대편 쓰레기 처리율이 0이다.
- 취수장은 하수 처리장에서 `DISCHARGE_RADIUS`(12) 밖에 둔다. 붙여 놓으면
  처리수에 남은 오염(0.15)을 그대로 다시 퍼 올린다 — 실제로 오염된 물을 마시는
  건물이 603채 나왔다.
- 상수관과 하수관은 빗살 두 개로 깔되 세로로 4칸씩 엇갈리고, 가지 끝도 반대쪽
  줄기에서 두 칸 앞에 멈춘다. 맞닿는 순간 `water.ts`가 상수도 전체를 오염으로
  본다. 가지는 양 끝에 딱 맞춰 균등하게 나눈다(고정 간격으로 위에서 찍으면
  아래 끝에 급수 사각이 생겨 급수율이 0.9996에서 멈췄다).
- 특수 시설도 함께 심는다: 교도소 1(경찰 서비스 보조), 통신탑 2(STEP 5 예약),
  항구 1(수역에 닿는 도시만). 항구는 하수 처리장이 인공 방류 수로를 파기
  **전에** 놓는다 — 안 그러면 도랑 옆에 항구가 선다.

### 2.7 생성할 때마다 다르다 (요구 4)

난수를 좌표 해시(`simRandom`)에서 **씨앗 기반 PRNG**(`src/world/rng.ts`,
mulberry32)로 바꿨다. 씨앗은 `macro.genSeed`에 저장한다(선택 필드라 옛 저장본은
그대로 열린다).

- 처음 접속: 씨앗이 없으면 도시 위치에서 만든 기본 씨앗을 쓰고 저장한다 →
  같은 학생은 다시 열어도 같은 도시를 본다.
- "맵 초기화": 새 씨앗을 뽑아 `macro.genSeed`에 적고 새로고침한다 → 누를 때마다
  다른 도시가 나온다.
- 같은 씨앗이면 언제 몇 번을 돌려도 같은 도시가 나온다(검사가 확인한다).

## 2.8 나란한 두 차선을 가로로 꿰지 않는다

처음 판에서는 뼈대를 세운 뒤 **맞닿은 도로를 전부** 이어 줬다. 격자에 사거리를
만들려면 필요한 처리인데, 나란히 붙은 도로 두 줄까지 가로로 전부 꿰어 버렸다.
화면에는 두 줄짜리 차선이 아니라 한 덩어리 넓은 아스팔트로 보이고,
`roadTileCapacity` 가 사거리(연결 4방향)를 0.5 로 깎으므로 통행량까지 줄었다.
측정하면 도시 하나에 사방으로 이어진 2x2 블록이 **275~292개** 였다.

예전 `citySeed.ts` 는 칸마다 앞뒤 7칸을 훑어 "이 도로의 주 진행축"을 추정하고
양쪽이 모두 직각 축이면 끊는 방식으로 이걸 막았다. 그 방식은 **짧은 구간에서
무너진다** — 두세 칸짜리 막다른 길이나 코너는 축을 정할 수가 없어서 평행
차선인데 잇거나, 반대로 멀쩡한 연결을 끊어 도로망을 조각냈다(1장의 도로망
분할이 바로 이것이다).

그래서 축을 추정하지 않는다. 간선 하나의 **양옆 2x2만** 본다.

```
A B     A-C 간선은 동쪽 옆칸 B, D 가 모두 도로이므로 가로대(rung)다
C D
```

사거리·T자·계단식 꺾임에는 2x2 가 생기지 않으므로 걸리지 않는다. 길이가 전혀
들어가지 않아서 두 칸짜리 평행 차선도 스무 칸짜리와 똑같이 잡힌다.

연결은 두 단계로 나눈다.

1. 도심에서 뻗어 나가는 단계에서는 가로대를 **미뤄 둔다.** 다른 경로로 끝내
   못 닿은 칸이 남았을 때만 그 가로대를 연다 — 그 가로대는 사다리 발이 아니라
   그 골목의 유일한 입구이므로 열어야 한다.
2. 도로 칸이 확정된 뒤 남은 맞닿음을 잇는 단계에서는 가로대를 하나도 열지
   않는다. 연결이 목적인 간선은 1단계에서 이미 열렸다.

`runLine` 의 한 칸 어긋남(shift)도 ±1 로 묶었다. 누적되면 선이 옆줄까지 흘러가
나란한 두 줄을 만든다.

| | 2x2 블록 | 사방 연결 | 사거리 |
| --- | ---: | ---: | ---: |
| 예전 생성기 | 311~459 | 13~29 | 154~225 |
| 첫 판(사다리) | 281~329 | **259~292** | 263~286 |
| 지금 | 295~327 | **0** | 150~183 |

## 2.9 빈 동네에만 시설을 한 채 더

사다리를 걷어내자 도로 거리가 실제 거리대로 늘어나면서, 개수 공식(정원 x 면적)이
**평균** 이라는 한계가 드러났다. 강이나 언덕이 길을 돌아가게 만든 쪽은 평균이
맞아도 비어서, 병원 커버율이 도시에 따라 0.72 까지 내려갔다.

상수를 올려 전부 촘촘하게 깔면 안 비는 동네까지 시설이 늘어 유지비만 는다.
그래서 **시뮬레이션이 쓰는 바로 그 `ServiceField` 로 재 보고**, 서비스가 안 닿는
건물이 몰려 있는 칸에만 한 채씩 더한다(최대 4회, 건물의 3% 미만이면 그만둔다).
생성기와 시뮬레이션의 커버리지 판정이 같은 코드라서 "생성기에서는 덮였는데
게임에서는 빈" 경우가 없다. 도시당 두어 채가 늘고 생성 시간은 그대로다.

## 4. 검사

`tools/check/cityGenCheck.ts`를 새로 넣고 `node tools/check/run.mjs citygen`으로
돌린다. 15개 항목이 위 불변식을 그대로 검사한다.

- 기본 2×2 청크 밖에 아무것도 쓰지 않는다
- 도로망이 언제나 한 덩어리다
- 연결된 모든 도로쌍이 `build.ts`의 연결 규칙을 통과한다
- 나란한 두 차선을 가로로 꿰지 않는다 (사방 연결된 2x2 도로 블록 0개)
- 학생이 생성 도로에 새 도로를 이어 붙일 수 있다
- 모든 건물이 도로에 맞닿는다 / 못 쓰는 지구 칸이 없다
- 주거·상업·공업이 모두 있고 비율이 목표 근처다
- 일자리 정원이 주거 정원의 균형식과 맞는다
- 필수·복지·위생·전력·상하수도 시설이 모두 선다
- 상수관과 하수관이 절대 맞닿지 않는다
- 씨앗이 다르면 다른 도시, 같으면 같은 도시
- 이미 지어진 도시는 건드리지 않는다
- 열흘을 돌려도 흑자이고 입주율이 건강하다

`tools/check/refactorScenario.ts`에서 생성 도시 두 개를 baseline 커밋과 바이트
비교하던 부분은 뺐다. 생성기를 **의도적으로** 다시 만들었으므로 그 비교는 더
이상 "리팩터가 동작을 안 바꿨다"를 뜻하지 않는다. 상수·매크로 이력·배정·저장
레이어의 동등성 비교는 그대로 둔다.

## 5. 함께 고친 것

- `World.placeGeneratedRoad` 추가. 생성 도로를 고립 상태로 놓는다. 예전에는
  `setBuild(..., byUser = false)`가 연결 비트를 `OVERRIDE_NONE`(사방 연결)으로
  남겨서, 비탈이든 평행 차선이든 맞닿기만 하면 전부 이어졌다.
- `World.connectRoads`에 `byUser` 인자 추가(기본값은 기존과 같은 `true`).
- `MacroState.genSeed` 추가(선택 필드).
- `tools/check/policySanitationCheck.ts`의 `only mini park is road optional`
  단언이 STEP 4.6 통신탑(kind 17, `needsRoad = false`)을 반영하지 못해 실패하고
  있었다. 이 검사가 전체 검사 실행을 막고 있어서 함께 고쳤다.

## 6. 알려진 사항 (이번 변경과 무관)

아래 두 가지는 이 작업 **전에도 main에서 실패하고 있었다.** 생성기를 쓰지 않는
손수 만든 픽스처 기반 검사라 이번 변경과 관계가 없어 손대지 않았다.

- `node tools/check/run.mjs service` — 23번 "필수 시설을 놓으면 입주율이
  회복된다" (24.09% → 24.08%)
- `node tools/check/run.mjs sim` — 220일 주행의 최종 입주율 25%가 목표 범위 밖
- `npm run check:parity` — 고정 baseline 커밋 `16b0b7c`가 현재 HEAD보다 23커밋
  뒤라, 그 사이의 의도된 밸런스 변경 때문에 이미 어긋나 있다. 기준 커밋 갱신이
  필요하다.
