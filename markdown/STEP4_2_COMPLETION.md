# STEP 4.2 — 상하수도 완료

기준: main `5d2d27e` (STEP 4.1). 이번 범위는 STEP 4.2이며 STEP 4.3 전기는 아직 구현하지 않았다.
사용자 요청대로 프로덕션 빌드와 핵심 동작만 검증했다.

## 사용 방법

1. 시설 메뉴의 ‘상하수도 시설’에서 급수시설과 하수시설을 각각 설치한다. 모두 도로에 닿아야 한다.
2. ‘상수도관’으로 급수시설부터 건물까지, ‘하수도관’으로 하수시설부터 건물까지 별도로 드래그한다. 건물·시설의 아래 칸 또는 바로 옆 테두리에 닿으면 연결된다.
3. 같은 종류의 관은 4방향 인접으로 자동 연결된다. 서로 다른 종류도 같은 지하 레벨에 있으므로 **겹치거나 옆으로 맞닿으면 상수도망이 오염된다.** 두 관 사이에는 빈 칸이 하나 이상 필요하다. 대각선 접촉만으로는 연결되지 않는다.
4. ‘배관 철거’는 해당 칸의 두 종류 배관만 지운다. 지상의 도로·건물은 보존한다. 일반 ‘철거’는 지상에만 적용한다.
5. 배관 도구와 상하수도 시설 도구에서는 지하 보기가 자동으로 켜진다. 다른 도구로 돌아가면 꺼진다. ‘배관 보기’를 별도로 켜면 선택 도구에서도 계속 볼 수 있다.

파랑은 상수도, 갈색은 하수도, 빨강은 오염된 상수도/혼합 접점이다.
도시 상태판에는 급수·하수 충족률, 연결된 총용량, 전체 수요, 오염수를 받는 건물 수를 표시한다.
건물을 선택하면 개별 급수·하수 충족률을, 시설을 선택하면 가동 상태와 연결망 수요/용량을 표시한다.

## 시설과 비용

| 시설 | kind / 저장 코드 | 도시 레벨 | 용량 | 건설비 | 하루 유지비 | 조건 / 배출 오염 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 지하수 펌프 | 7 / 16 | 1 | 1,000 | 3,000 | 90 | 평지 + 도로 + 상수도관 |
| 하천 취수장 | 8 / 17 | 2 | 4,000 | 8,000 | 180 | 하천 인접 육지 + 도로 + 상수도관 |
| 직접 방류구 | 9 / 18 | 1 | 1,500 | 2,000 | 50 | 하천 인접 육지 + 도로 + 하수도관 / 100% |
| 하수처리장 | 10 / 19 | 3 | 5,000 | 12,000 | 240 | 하천 인접 육지 + 도로 + 하수도관 / 15% |

배관은 종류별 칸당 건설비 12, 하루 유지비 0.05다. 같은 칸에 같은 관을 다시 칠하면 추가 비용이 없다.
용량·단가는 이번 단계에서 정한 초기 밸런스이며 장기 튜닝은 하지 않았다.

## 관망과 오염 규칙

- 상수도망과 하수도망은 종류별로 별도 계산한다. 인접 오접속은 오염을 전달하며, 하수도관이 상수도관 역할을 대신하지는 않는다.
- 수요는 주거 정원과 상업·공업 일자리 정원을 합산한다. 실제 입주율 대신 정원을 사용해 ‘급수 부족 → 퇴거 → 수요 감소 → 재입주’ 반복을 피한다.
- 연결망마다 공급/처리 용량을 합산한다. 부족하면 연결된 모든 건물에 같은 충족 비율을 적용한다. 다른 독립 관망의 남는 용량은 가져오지 않는다.
- 한 시설이 여러 독립 관망에 닿으면 시설 용량을 균등 분배한다. 건물은 종류별로 닿는 관망 중 용량이 가장 큰 하나를 사용한다. 시설·건물이 떨어진 관망을 물리적으로 이어주지는 않는다.
- 도로 연결이 끊기거나 필요한 하천이 없어지면 시설이 멈춘다. 가동 중지 시설도 유지비는 낸다.
- 하수 수요가 연결된 가동 중 방류시설은 반경 12타일 안 하천 취수장에 거리 감쇠 오염을 준다. 하수처리장의 배출 오염은 직접 방류구의 15%다. 여러 급수원이 같은 관망에 있으면 취수장 용량 비율만큼 섞인다.
- 하천 오염은 시설 위치를 기준으로 계산하는 국소 근사 모델이다. 실제 물 흐름, 상·하류, 수계 연결 추적, 지하수 고갈은 이번 범위에 없다. 지하수 펌프는 하천 방류 오염을 받지 않지만 배관 혼합 오염은 받는다.
- 오염된 물은 만족도 감점(최대 0.2)과 기존 질병 발생 확률 상승(최대 5배)에 연결된다. 기존 병원 예방 효과와 소도시 재해 유예는 유지한다.
- 급수 부족 최대 0.18, 하수 부족 최대 0.12의 만족도 감점을 추가한다. 기존 서비스와 합친 감점 상한 0.5를 유지한다. 계층별 인프라 민감도 강화는 STEP 4.8로 남긴다.

## 저장·호환·구현 위치

- 시설은 기존 `Build.Civic`, `FAC_BASE`, `bld` 저장 구조를 확장했다. 지구 건물 코드 0~8, 기존 시설 9~15는 그대로다. 새 시설만 16~19를 사용한다.
- `isWelfareKind`는 4~6만 복지로 분류한다. 수도 시설은 학교·병원 커버리지나 공원 점수로 계산하지 않는다.
- 청크 선택 필드 `pipes`: 255=없음, 1=상수도, 2=하수도, 3=두 종류 겹침. 기존 RLE/base64 압축과 청크 스냅샷에 포함한다. 배관만 있는 청크도 저장·로드·메모리 언로드 때 보존한다.
- 옛 저장본의 배관은 없음으로 읽는다. `macro.waterStartTick`을 최초 적용 틱으로 저장해 30게임일 동안 부족 감점을 유예하고, 이후 30일 동안 점진 적용한다. 재접속으로 유예가 갱신되지 않는다. 오접속에 의한 오염 감점은 유예하지 않는다.
- 맵 초기화 시 배관과 유예 시작값을 함께 초기화한다. 현재 자동 생성 대도시에 배관을 자동 시공하지는 않는다.
- `src/sim/config/water.ts`: 시설 용량, 배관 비용, 오염 반경, 유예 기간.
- `src/sim/water.ts`: 변경 revision에 따른 관망 재구성, 공급/하수/오염 상태.
- `src/render/waterLayer.ts`: 지하 보기 전용 Graphics 오버레이. 기존 지형·건물의 청크 메시 구성과 교통 규칙은 보존했다.
- 기존 7종 시설 그림 파일은 변경하지 않았다. 런타임 아틀라스를 768×384로 확장하고 빈 열에 4종 시설을 코드로 그린다. 기존 아트 생성 도구는 계속 원본 7종을 생성한다.

## 검증

- `npm run build` 통과: TypeScript + Vite 프로덕션 빌드. 기존 Pixi 번들 500 kB 경고만 있다.
- `node tools/check/run.mjs water` 통과: 급수/하수 분리, 시설 잠금/하천 조건, 인접/동일 칸 오염, 배관 단절·복구, 도로 해제, 처리장 오염 감소, 용량 초과·증설, 청크 경계 연결과 저장 복원, 철거·초기화, 질병 발생 경로, 유예 유지.
- `node tools/check/run.mjs atlas progression`에 해당하는 두 검사도 통과: 기존 7종 아트 보존/새 4종 아트 가시성, STEP 4.1 레벨·저장 연결.
- 전체 교통/서비스 회귀검사, 브라우저 시각 확인, 실제 Firebase 왕복 저장, 장시간 성능·밸런스 검증은 생략했다. Claude 후속 검증 대상으로 남긴다.
